# 落地前代码审查报告

审查对象：`a7z-local-route`（3 个待落地文件 + 安装脚本）
审查日期：2026-11-05

## 审查方式

| 手段 | 说明 |
|---|---|
| 静态检查 | `bash -n` 语法；逐行审读；命名/注释/复杂度/死代码/注入面 |
| 分支行为验证 | 把 `ip` / `flock` mock 掉跑真脚本，**9 个场景 21 项断言**，不碰真机 |
| 逻辑单测 | `has_rule` 的规则匹配单独测 4 个用例（含子串陷阱） |
| 交叉审查 | oracle 尝试 5 次均失败（见末节），改用人工逐面审查 + 可粘贴 review pack |

## 发现并修复的问题

| # | 级别 | 问题 | 修复 |
|---|---|---|---|
| 1 | **高** | 用 `grep -F "to X lookup 100"` 判断规则是否存在，会把 `lookup 1000` 误判成命中 → 规则永远不加，功能静默失效 | 改为 `awk` 逐字段比较（单测 T4 验证） |
| 2 | **高** | 判断「wlan0 是否属于该网段」时 `head -1` 只取第一个地址，多地址/别名场景漏判 | 改为取全部直连网段 + `grep -qxF` 精确比较 |
| 3 | **高** | NM dispatcher 的 `up` 与 `dhcp4-change` 可能并发，两个实例各自通过 `has_rule` 判断后各插一条同优先级规则（Linux 允许并列，规则变脏、回滚易漏删） | 加 `flock -n` 非阻塞锁，拿不到就退出 |
| 4 | 中 | 优先级 `5260` 若已被别的规则占用，`ip rule add` 仍返回 0 但行为不确定 | 先检查占用，占用则 WARN 并跳过，不硬插 |
| 5 | 中 | 日志只走 `logger`（syslog）；最小系统无 `logger` 时完全没有记录 | 改为 **stderr 优先**（systemd 收进 journal）+ 尽力写 syslog |
| 6 | 中 | 清条目时 `ip route flush table 100` 过于粗暴，会误删将来可能加入的其它条目 | 改为精确 `ip route del <net> dev <iface> table 100` |
| 7 | 低 | 配置文件语法错误时 `source` 静默失败，用户以为生效了 | 加 WARN 明确提示 |
| 8 | 低 | 生命周期/归属/局限未写明 | 文件头补【约定】表 100 独占、【局限】只处理单个 IFACE |

## 验证结果

**9 场景 / 21 断言全过**：

| 场景 | 断言要点 |
|---|---|
| S1 在家 | 加规则 + 写直连条目 + 不误删 |
| S2 在车里 | 规则保留、条目清空（**保证「在车里访问家里内网」不被破坏**） |
| S3 幂等 | 重复执行不重复加规则 |
| S4 无 wlan0 | 零写操作 + 退出日志 |
| S5 子串陷阱 | 已有 `lookup 1000` 仍能加 `lookup 100` |
| S6 有网卡无地址 | 清空条目、回落 Tailscale |
| S7 优先级被占用 | 告警跳过、不硬插、仍同步条目 |
| S8 持锁 | 立即退出、零写操作 |
| S9 锁文件不可写 | WARN 后继续执行 |

## 审查中修正的测试自身缺陷（避免假通过）

| 现象 | 真实原因 |
|---|---|
| 首轮 8 项全红、mock 一次没被调用 | `mktemp -d` 落在系统 Temp，bash 读不到 → mock 未创建 → 脚本回落到真 `ip` |
| 测试进程被 SIGTERM 杀死且无输出 | 脚本里的递归删除命令触发沙箱删除保护 |
| S5 卡死 | mock 的 `logger` 在 MSYS 下反复 fork 会挂 → 顺带促成「stderr 优先」的日志改进 |
| S9 误报通过 | `run_case` 无条件覆盖了 `A7Z_LOCK_FILE`，把不可写路径冲掉了 |

**教训**：测试红的时候先分清「产物错」还是「断言错」——本次 4 次都出现过，
只有 #1/#2/#3 是真问题，其余是测试自己的坑。

## oracle 交叉审查：本机不可用（第 5 次尝试）

| # | 错误 | 判断 |
|---|---|---|
| 1-4 | `No Chrome installations found` / `Chrome window closed before oracle finished` | 本机只有 Playwright Chromium，无系统 Chrome；指定 `CHROME_PATH` 后窗口被关 |
| 5 | `Prompt textarea did not appear before timeout` | 浏览器起来了，但 ChatGPT 页面输入框未就绪（未登录或页面结构变化） |

本机也无 `OPENAI_API_KEY` 等 API 凭据；`--render` 只导出 prompt 骨架、不内联 `--file` 内容。

**替代**：`oracle-review-pack.md` —— 手工拼装的「审查 prompt + 3 个文件全文 + 已做验证清单」，
可直接粘贴到任意 LLM 做第二意见。prompt 里已明确「已做过哪些验证，不必重复提」。

## 结论

三个文件**可以落地**。剩余风险均为已知且可接受：

- dispatcher 执行耗时 < 100ms（A7Z 上外部命令 ~10ms/次，共 7 次），远低于 NM 超时
- 开机时 wlan0 未连上 → oneshot 只清空表 100（无害），之后由 dispatcher 补齐
- 规则永久常驻但表为空时不影响任何流量（自然回落 Tailscale）
- 回滚覆盖全部 4 个安装位置 + 运行时规则/表
