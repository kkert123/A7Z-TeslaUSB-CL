## 诊断：12.127.12.126:5000 打不开，只有 100.116.18.42:5000 可用

**根因：Tailscale subnet route 抢走了本地直连网段的路由（不是防火墙、不是服务未监听）。**

证据链（全部实测）：
- 设备 wlan0 = `12.127.12.126/24`，网关 `12.127.12.40`，SSID `C12345`
- 本机 = `12.127.12.122`（MAC `BC-24-11-16-C0-AE`），**与设备同一 /24**
- ARP 双向解析正常（本机 ARP 有设备 MAC `bc-2a-33-96-a9-be`；设备 ARP 有本机 MAC，REACHABLE）→ **二层通**
- 设备 `iptables INPUT policy ACCEPT`，DROP 只有 139/137-138 → 防火墙排除
- 设备 self-curl `12.127.12.126:5000` → **200**，服务正常
- **决定性**：设备 `ip route get 12.127.12.122` → `dev tailscale0 table 52 src 100.116.18.42`
  即回包走 tailscale 隧道、源 IP 变成 100.116.18.42 → 本机 4 元组不匹配 → 丢弃
- `ip rule`：`5270: from all lookup 52` 优先于 `32766: lookup main`；
  `table 52` 有 `12.127.12.0/24 dev tailscale0`
- 宣告者是 **`Docker`（100.106.205.21）** 的 `PrimaryRoutes = ['12.127.12.0/24']`
- A7Z `RouteAll: true`（accept-routes 开启）→ 接受该 subnet route
- 旁证：设备 ping `.242`（在 Docker 网段内）通 7–34ms；ping `.122`（本机）不通；
  `ip route get 12.127.12.8/.245/.40` **全部走 tailscale0**

**为什么 100.116.18.42:5000 能开**：双向都走 tailscale0，4 元组一致。

**修复选项**（待用户确认，未动）：
- **A（推荐）** `sudo tailscale set --accept-routes=false` —— A7Z 是终端，不需要接受 subnet route；
  关掉后 `12.127.12.8/.245` 的 ping 也回到 wlan0 直连（本来就是要测本地 WiFi），双重收益
- B Docker 主机取消宣告 12.127.12.0/24（治本，但影响其它节点的远端访问）
- C A7Z 加 `ip rule add to 12.127.12.0/24 lookup main priority 5260`（保留 accept-routes）
- D 不改，继续用 100.116.18.42

**顺带核实**：`_check_connectivity()` 有 `_wifi_associated()` 前置 + `baidu.com` 兜底，
所以误判风险有限（不是原先担心的"车在外被判在家"）；但探测目标绕 tailscale 确实
不达本意，方案 A 可一并修正。

**方法论**：这类"同网段却互 ping 不通"先查 `ip route get <对端>`，一眼看出回包走错接口，
比抓包快得多；再 `ip rule` + `table 52` 定位是谁注入的路由。

## 条件化路由方案已实机验证（未持久化）

用户确认**需要**"在车里（车载热点 192.168.8.x）通过 A7Z 访问家里 12.127.12.x 内网"，
所以不能直接关 accept-routes，改用**专用表 + 高优先级 ip rule**：

```
ip route replace 12.127.12.0/24 dev wlan0 table 100      # 注意：带 src 会报 Invalid prefsrc
ip rule add to 12.127.12.0/24 lookup 100 priority 5260   # 5260 < tailscale 的 5270
```
- 表 100 **有**该网段 → 走 wlan0 直连（在家场景）
- 表 100 **空** → 继续查 5270 → table 52 → tailscale（车载热点场景）✓

**实机验证结果**：`ping 12.127.12.115` 0% 丢包 3-4ms；`curl 12.127.12.115:5000` → 200 / 0.72s。
验证后已清理（`ip rule del` + `ip route flush table 100`），恢复原状。

**重要发现：设备 wlan0 地址已从 12.127.12.126 变成 12.127.12.115**（DHCP 换租），
所以用户看到的 `.126` 本身就是过期地址 —— 即使修好路由也不能依赖固定 IP。
建议：家里路由器给 A7Z MAC 做 DHCP 静态绑定，或直接用 100.116.18.42。

**持久化落点已确认**：`/etc/NetworkManager/dispatcher.d/`（已有 `01-ifupdown`、`90-tesla-sync`），
NM active。方案 = 脚本 `/usr/local/sbin/a7z-local-route.sh`（不受升级包覆盖）
+ NM dispatcher `91-a7z-local-route`（up/dhcp4-change/down）+ systemd oneshot 开机兜底。
**待用户确认后实施**。
