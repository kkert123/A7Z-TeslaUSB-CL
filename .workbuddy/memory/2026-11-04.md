## 评审：Web 认证 B 方案细化（密码 + 邮箱动态验证码）

**产出**：`docs/explanation/Web认证-密码与邮箱动态口令方案评审.md`（设计评审，未实施）

### 评审前实测到的三条关键事实（直接影响设计）

1. **设备时钟不可信**：11-04 09:25 开机 → **10:53 才首次 NTP 同步（87 分钟）**，期间 10:40 一次 `Timed out`；历史有 `clock time jumped backwards`。→ OTP 有效期/锁定窗口全部依赖时钟，必须有「时钟未同步拒签 OTP」分支。
2. **项目零邮件能力**：全仓库 `grep smtplib/SMTP` 零命中 → 邮件通道是全新依赖（发送模块 + 失败重试 + 送达率处理都要新建）。
3. **可复用资产**：`templates/login.html`（253 行，含用户名/密码表单）**已在升级包白名单但无任何路由渲染**；设置页 `templates/system.html` 有 9 个 `grp-*` 分组 → 新增 `grp-security` 顺理成章，实施成本低于从零。

### 核心评审结论

- **最大缺陷**：「无网络 → 只验密码」是**降级攻击面**：攻击者只要让设备发不出邮件（断网/封 SMTP/开到无信号处）就能把双因子压缩成单因子。建议改为「密码 + 离线恢复码」保持双因子；若要单密码，必须限本地网络 + 显式开关 + 每次告警。
- **判定条件不能用"有没有网络"**：网络通 ≠ SMTP 可用（封 25 端口、DNS 失败、TLS 过期、服务商限流）。应分层探测，并以「最近一次真实发信成功」为强判据。
- **6 位码的安全性来自限流而非位数**：有效期 5 分钟、单码 3 次、重发 60s、单 IP 10 分钟 5 次、全局 10 分钟 10 次 / 每日 20 次；失败锁定 + **本地网络优先通道**（防配额被刷爆导致主人自锁）。
- **邮箱作为第二因子的真实强度 ≈ 邮箱本身强度**（手机邮件 App 常驻登录时几乎等于"密码+密码"）；发送邮箱与安全邮箱必须不同账号，发送邮箱用「应用专用密码/仅发信」权限。
- 长期建议：**用 TOTP 替代邮箱验证码作主第二因子**（离线可用、不依赖送达率），邮箱码降级为备用通道；术语上「动态口令」应专指 TOTP，邮件 6 位码叫「邮箱验证码」。
- 顺手发现：`config_manager.save_config()` 也是 `json.dump` 直写（非原子）→ 存密码哈希/邮箱凭据前必须先改成 `mkstemp + os.replace`（M114 同类）。

## 登录鉴权设计定稿（用户已确认 6 条决策）

**产出**：`docs/explanation/登录鉴权设计说明-已确认方案.md`

**用户决策**：① 在线判据=最近一次真实发信成功（10 分钟内新鲜）+ 发信频率限制防轰炸；② 术语：6 位码=邮箱验证码，「动态口令」仅指 TOTP（本期不实现）；③ 离线兜底=**直接密码**（不用恢复码、不上 TOTP）；④ 单账号；⑤ 首次启用仅本地网络 + 测试码闭环；⑥ 安全邮箱禁止 tailnet 远程修改，只能走正常 Web 页面。

**设计要点（新增的、非用户原话）**
- **密码通过后才发码**：用户说"靠频率限制防匿名触发发信"，更彻底的做法是"没密码根本不发信"，频率限制降为第二道闸。
- **时钟问题用单调时钟解决**：TTL 判定改用 `time.monotonic()` 差值，NTP 校时/回跳不再影响验证码有效期；重启后回退 wall 时间并打 `clock_fallback=wall` 标记。这样**不需要因时钟未同步而拒绝发码**。
- **本地网络判定**是 D4/D6/D7 三处共用的基础设施：`127.0.0.1` + 局域网段 + `192.168.42.0/24`；`100.64.0.0/10` 明确判为非本地；不信任 `X-Forwarded-For`。
- **R6 补充**：全局锁定期间，本地网络的密码校验仍放行 1 次/5 分钟，防"攻击者刷锁定把主人锁在门外"。
- **前置必修**：`config_manager.save_config()` 是 `json.dump` 直写（非原子，M114 同类），存密码哈希前必须先改 `mkstemp + os.replace`。

**参考页 `http://12.127.12.228/ups_stats.php` 的对照结论**
- 借鉴：400px 白卡片、60s 倒计时按钮、脱敏邮箱提示、`{status,msg}` 简单返回。
- **不借鉴（关键）**：参考页是两个 tab **二选一**（密码 OR 验证码），本方案是**先后两步 AND**；且参考页用 Bootstrap CDN——**A7Z 常在无外网环境（AP/车内），CDN 拉不到会让登录页样式崩坏**，必须沿用自有 `static/style.css`。

**待定**：局域网段配置方式、SMTP 服务商（影响端口/授权码）、是否支持踢出其它会话、`?next=` 跳转（需防开放重定向）。

## 方案改为「仅验证码登录」（v2，推翻 v1 的密码模型）

**产出**：`docs/explanation/登录鉴权设计说明v2-仅验证码登录.md`；v1 文档已标「已作废」。

**用户新决策**：① 仅验证码登录，无密码、无定期改密；② 「未生成有效验证码就不发信」，限流降为第二道防线；③ 局域网段**手填**、SMTP 用**腾讯企业邮**、登录成功**踢出其它会话**。

**关键设计与我的补充**
- **"合法性"用 challenge 票据而不是限流**：`GET /login` 签发 HMAC 票据（nonce+时间+IP/UA 指纹，5min、一次性）。发码前四道闸：票据有效 → UA 一致 → 该票据下无未过期有效码 → **验证码已生成并 fsync 成功**；四道全过才走 SMTP。限流是第五层，只兜底。
- **踢人用 session_epoch**（落盘整数 +1），不维护会话列表；多标签页共享 Cookie 不互踢；注销不改 epoch。
- **腾讯企业邮**：`smtp.exmail.qq.com` 465 SSL（首选）/587 STARTTLS；账号=完整邮箱；开了安全登录必须用 **16 位客户端专用密码**。前置条件常被忽略：**管理员需在企微管理端【协作→邮件→安全管理→客户端访问权限】开 POP/IMAP+SMTP 范围**，成员再在网页版【设置→收发信设置】开启。
- **局域网手填的两个坑**：AP 段 `192.168.42.0/24` 必须内置不可删（否则连自己热点都不算本地）；保存新网段时**不校验当前 IP 是否在内**（否则改网段会自锁），但要在页面提示"保存后可能失去权限"。
- **?next= 详解已写进文档 §8**：作用（登录后回原页）、开放重定向的三类变体（`//evil.com`、`/\evil.com`、`%2f%2f`、`https:evil.com`、`@` 混淆）、在白名单式校验（scheme/netloc 必须为空、只解码一次、单斜杠开头）；**推荐 §8.4 服务端暂存意图**，让 URL 里根本没有可篡改的跳转目标——无密码方案下这点更重要，因为**没有密码可骗，验证码就成了 OTP 钓鱼的唯一目标**。

**必须用户决策的硬缺口**：仅验证码方案下，设备无外网 = 发不出码 = 无法登录。给了 L1（本地免码）/ L2（本地密钥）/ L3（离线禁登）/ L4（离线只读）四个选项，建议 **L2+L4**：L1 的风险是"蹭网者可控设备并删除哨兵录像"（不可逆）。

## 真机影子验证（2026-11-05 00:30，未发布版本 v0.3.1.68）

**约束**：不改动运行中的 v0.3.1.67。做法：包传到 `/tmp`、解压 `/tmp/v168-shadow`、
脚本里把 `config.DATA_DIR` 指到 `/tmp/.../_shadow_data`，用 Flask test_client 跑完整链路。
**不碰 /opt、不占 5000、不重启服务、不动 symlink。**

**结果 35/35 通过**（设备 Python 3.9.2 / Flask 3.1.3 / Jinja2 3.1.6）。

**真机才暴露的真 bug（最重要）**
`get_secret_key()` 只认 `/data/.secret_key`（设备上 root 600）。读不到时它**每次返回新的随机密钥**，
异常被 `except OSError: pass` 吞掉 → challenge 签名密钥与校验密钥不一致 → 所有票据 `bad_signature`。
本地测试因为把 `SECRET_FILE` 指到临时目录而恰好避开这个坑。
修法：多候选（`/data/.secret_key` → `DATA_DIR/.secret_key`）+ 进程内缓存 + 读写失败打 warning。
真机复测：告警可见、自动回退、check 通过。

**环境未变证据**：symlink 仍 v0.3.1.67、服务 active、`uptime -s` 与基线一致、5000 仍是原 pid 442、
`/opt/radxa_data/teslausb-v0.3.1.67` mtime 仍是 Nov 3 19:26。

**结论**：本地方案（临时目录覆盖）会掩盖"路径不可写/不可读"这类真实环境问题——
影子验证必须用**设备真实权限**跑，否则测的是理想环境。
