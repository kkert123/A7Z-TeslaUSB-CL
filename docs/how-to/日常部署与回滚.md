# 日常部署与回滚

> 场景：本地改完代码，要上到设备；或者刚上的版本有问题，要退回去。

---

## 部署单个文件

`deploy_manager.py` 是唯一入口。它会先备份远程文件、再上传、再 SHA256 校验、最后重启服务。

```bash
python deploy_manager.py deploy -f wifi_service.py -m "修复 AP 扫描轮询" -y
```

参数说明：

| 参数 | 作用 |
|------|------|
| `-f` | 逗号分隔的文件列表，路径相对于仓库根 |
| `-m` | 版本备注，会记进版本历史，回滚时靠它认版本 |
| `-y` | 跳过确认（脚本化时用） |

先干跑看会动哪些文件：

```bash
python deploy_manager.py deploy -f wifi_service.py -m "test" --dry-run
```

## 部署多个文件

```bash
python deploy_manager.py deploy -f app.py,utils/cache_coherency.py,routes/video_routes.py -m "缓存刷新双语义" -y
```

## 新增文件必须先加白名单

**这是最容易漏的一步。** `deploy_manager.py` 的 `Config.MANAGED_FILES`（当前 106 项）是唯一的文件管理清单。不在白名单里的文件：

- `deploy` 会直接拒绝
- 即使手工传上去，也会被排除在升级包之外 —— 换机或全新部署时文件就丢了（[M36](../reference/教训索引.md)）

```python
# deploy_manager.py
class Config:
    MANAGED_FILES = [
        "app.py",
        # ... 新增的模块加在这里
    ]
```

## 回滚

```bash
# 看版本历史
python deploy_manager.py versions

# 回退到上一个版本
python deploy_manager.py rollback

# 回退到指定版本
python deploy_manager.py rollback v123
```

回滚会用部署前的远程备份覆盖回去，然后重启服务。

## 手工部署（调试用）

有时候只想快速验证一个文件，走 SCP 更直接：

```bash
scp utils/cache_coherency.py radxa@100.116.18.42:/opt/radxa_data/teslausb/utils/
```

**但重启必须完整三步**：

```bash
sudo systemctl stop teslausb-web
sudo find /opt/radxa_data/teslausb -name '__pycache__' -type d -exec rm -rf {} +
sudo find /opt/radxa_data/teslausb -name '*.pyc' -delete
sudo systemctl start teslausb-web
```

> 只用 `systemctl restart` 不够。Flask 的模板和 `.pyc` 会被缓存住，改了不生效，表现为「明明传上去了但行为没变」。

验证：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:5000/
```

## 部署后必做

1. **看日志有没有异常刷屏**
   ```bash
   journalctl -u teslausb-web -n 50 --no-pager
   ```
   子进程调用如果没做节流，几十秒内就能刷出几百行，直接把 Web 拖垮（[M34](../reference/教训索引.md)）。

2. **确认服务真的起来了**，不是「restart 命令返回 0」就完事：
   ```bash
   systemctl is-active teslausb-web
   ```
   升级流程里尤其要注意 —— 必须用 root 身份直接调 systemctl，然后轮询 `is-active` 确认（[M43](../reference/教训索引.md)）。

3. **前端改动检查语法**
   ```bash
   node --check static/app.js
   ```
   手工编辑 JS 极易留下乱码或未定义变量，一个 ReferenceError 会让后续所有渲染停摆（[M22](../reference/教训索引.md)）。

## 部署检查清单

- [ ] 新增文件已加入 `MANAGED_FILES`
- [ ] Python 语法检查通过（`python -m py_compile`）
- [ ] 前端改动 `node --check` 通过
- [ ] 涉及多模块读写同一配置的，路径一致（[M19](../reference/教训索引.md)）
- [ ] 多线程共享状态的地方加了锁（[M32](../reference/教训索引.md)）
- [ ] 子进程调用有节流/缓存
- [ ] 部署后看了日志，无异常刷屏
- [ ] 知道怎么回滚（版本号记下）
