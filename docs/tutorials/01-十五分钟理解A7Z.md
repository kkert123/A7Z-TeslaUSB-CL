# 15 分钟理解 A7Z

> 读完你会知道：这个系统解决什么问题、数据怎么流动、出问题时该往哪个方向查。

---

## 它到底在解决什么问题

特斯拉的原厂行车记录仪只能把视频写到 U 盘。U 盘容量有限、取下来麻烦、被砸窗了视频也跟着丢。

A7Z 的思路是：**用一块小单板电脑伪装成 U 盘**。车机以为自己在往 U 盘写，实际上写进了 A7Z 的 NVMe 硬盘；A7Z 同时连着 WiFi，写完就往企业微信推送、往 NAS 或云端备份。

对车机来说它是个 U 盘，对网络来说它是台服务器。这就是全部。

---

## 硬件

| 部件 | 型号 | 说明 |
|------|------|------|
| 主板 | Radxa Cubie A7Z | Allwinner A733，Cortex-A55×6 + A76×2 |
| 内存 | 959MB 可用 | **很小**，这是很多设计决策的根源 |
| 存储 | KIOXIA 256GB NVMe | exFAT 分区，车机只认 exFAT/FAT32 |
| 无线 | AIC8800 | WiFi + 蓝牙，AP 与 station 双模 |
| 系统 | Debian 11 (bullseye) aarch64 | Radxa 官方 A733 镜像 r6 |

内存只有 959MB 这件事，后面会反复出现。**任何涉及缓存、并发转码、子进程数量的决策，都要先问一句：959MB 撑得住吗。**

## 数据是怎么流动的

```
特斯拉车机
    │  USB（车机写，A7Z 是 device 端）
    ▼
A7Z ── USB Gadget ── /dev/nvme0n1p2（exFAT）
    │                      ▲
    │                      │ 本地只读挂载 /mnt/teslacam
    │                      │
    ├──► 哨兵 watchdog ────┘  检测新文件 → 转码缩略图 → 企业微信推送
    ├──► Web 服务 :5000        浏览、播放、下载
    ├──► 同步服务              NAS 备份（timer 触发）
    └──► 云归档               rclone → 14 家云盘
```

三条链路的触发方式不同，排障时先分清是哪条：

| 链路 | 触发者 | 出了问题看什么 |
|------|--------|---------------|
| 车机写入 | 车机 | `journalctl -u teslausb-gadget`，车机屏幕报错 |
| 检测推送 | `teslausb-sentry` | `/var/log/teslausb-sentry.log` |
| 浏览播放 | 用户点 Web | `/var/log/teslausb.log` |

## 两种运行模式

这是理解 A7Z 的关键，很多奇怪行为都源于它。

| | **Present 模式** | **Edit 模式** |
|---|---|---|
| 用途 | 插在车上，车机读写 | 取下来维护 |
| USB Gadget | **绑定中**，车机可写 | 已拆除 |
| 分区挂载 | 只读 `/mnt/teslacam` | 读写 + fsck |
| 谁能写盘 | 只有车机 | 只有本机 |
| 典型问题 | 读到的内容货不对板 | 车机认不出设备 |

**为什么要只读挂载？** 因为车机通过 Gadget 写盘时，本机和车机看到的是两块不同的缓存。如果本机也挂载成可写，两边同时写同一个 exFAT 分区，文件系统必坏。

代价是：车机写了新内容，本机的缓存不会自动失效，读到的还是旧数据。这个问题单独成文，见[缓存一致性](../explanation/缓存一致性.md)。

## 关键模块速查

不用一次记全，知道去哪找就行。

| 模块 | 干什么 |
|------|--------|
| `app.py` | Flask 入口，装配所有路由 |
| `config.py` | **所有路径常量的唯一来源**，改路径先改这里 |
| `teslausb-gadgetd.py` | Gadget 守护进程，管 UDC 绑定 |
| `sentry_watchdog.py` | 哨兵事件检测主循环 |
| `weixin_notifier.py` | 企业微信推送（双机器人） |
| `wifi_service.py` | WiFi 双模 + AP 自愈（**最大的单文件，11 万字节**） |
| `utils/cache_coherency.py` | VFS 缓存刷新策略 |
| `deploy_manager.py` | 部署与回滚 |
| `upgrade_service.py` | 升级包校验（SHA-256 + Ed25519 验签） |

完整的模块清单见 [参考 · 路径与配置项](../reference/路径与配置项.md)。

## 出问题时先分清四件事

排障的绝大部分时间花在定位上。按顺序问：

1. **是车机侧还是 A7Z 侧？** 车机屏幕报错 → 车机侧；Web 打不开 → A7Z 侧
2. **是 Present 还是 Edit 模式？** `cat /tmp/teslausb_mode`
3. **服务在跑吗？** `systemctl status teslausb-web teslausb-sentry`
4. **最近改了什么？** 90% 的线上问题是最近一次部署引入的

然后去 [排障手册](../how-to/排障手册.md) 按症状查。
