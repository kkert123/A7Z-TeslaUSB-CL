# 接管一台新设备

> 场景：拿到一台刷好 Radxa 官方镜像的 A7Z，或者旧设备要重刷。
> 目标：车机能识别成 U 盘、Web 界面能打开、哨兵事件能推送。
> 预计耗时：40 分钟（不含系统刷写）

---

## 前置条件

- [ ] Radxa 官方 A733 Debian 11 镜像（r6 或更新）已刷入
- [ ] 能通过 SSH 登录（默认 `radxa` / `radxa`）
- [ ] NVMe 已分区为 exFAT
- [ ] 你有仓库的读取权限

连上设备：

```bash
ssh radxa@<设备IP>
```

如果不知道 IP，先接串口或从路由器后台看 DHCP 租约。

---

## 第 1 步：建立远程通道

A7Z 常年放在车里，靠 Tailscale 远程访问。先装它：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh
```

> ⚠️ 不要用 `tailscale up --ssh` 之外的参数组合覆盖，也**不要**让它接管 22 端口后再用 paramiko 连 —— 会认证超时（见 [教训索引 M24](../reference/教训索引.md)）。用系统 SSH 客户端连。

记下分配到的 Tailscale IP，后面所有操作都用这个地址。

---

## 第 2 步：拉取代码

设备上是裸目录，没有 git 仓库，需要先 git 化（[M27](../reference/教训索引.md)）：

```bash
sudo mkdir -p /opt/radxa_data
cd /opt/radxa_data
sudo git clone git@github.com:kkert123/A7Z-TeslaUSB-CL.git teslausb
cd teslausb
git log --oneline -3        # 确认拉到了
```

如果 SSH 通道不通（github.com:443 被阻断），改用 HTTPS，或者在 `~/.ssh/config` 里把 HostName 指向 `140.82.112.3`（[M48](../reference/教训索引.md)）。

---

## 第 3 步：装依赖

```bash
python3 -m venv /opt/radxa_data/venv
source /opt/radxa_data/venv/bin/activate
pip install -r requirements.txt
```

> `requirements.txt` 必须存在且完整。它一旦缺失，新 venv 装不出依赖，Web 服务起来就是 502（[M33](../reference/教训索引.md)）。

---

## 第 4 步：装 systemd 单元

`services/` 下的所有 `.service` 和 `.timer` 都要装：

```bash
cd /opt/radxa_data/teslausb/services
sudo cp *.service *.timer /etc/systemd/system/
sudo cp *.sh /opt/radxa_data/teslausb/
sudo chmod +x /opt/radxa_data/teslausb/*.sh
sudo systemctl daemon-reload
```

> Windows 上打的 tar 包会丢执行位，解压后必须统一 `chmod +x *.sh`（[M35](../reference/教训索引.md)）。

逐个启用，完整清单见 [服务清单](../reference/服务清单.md)。最小可用集：

```bash
sudo systemctl enable --now teslausb-web teslausb-sentry teslausb-gadget
```

---

## 第 5 步：部署 udev 规则

```bash
sudo cp udev/99-usb-gadget.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
```

v0.3.1.40 起升级包会自动部署这条规则，但全新装机仍要手动做一次。规则的作用和为什么长这样，见 [USB Gadget 与车机交互](../explanation/USB-Gadget与车机交互.md)。

---

## 第 6 步：配置

需要配的东西都在 `config/` 下：

| 文件 | 内容 |
|------|------|
| `config/sentry.json` | 企业微信 Webhook、哨兵开关 |
| `config/rclone/rclone.conf` | 云盘远程（可选） |
| `config/config.json` | 应用级设置 |

可以从示例复制后编辑：

```bash
cd /opt/radxa_data/teslausb/config
cp ../../weixin_config.example.json sentry.json
```

> 这些文件**不会**进升级包，也不会进 git（`.gitignore` 已排除）。换设备要单独迁移。

---

## 第 7 步：验证

按顺序确认每一环：

```bash
# 1. Web 起来了
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:5000/
# 期望 200（未登录会 302 到 /login，也算通）

# 2. 服务状态
systemctl is-active teslausb-web teslausb-sentry teslausb-gadget

# 3. Gadget 已绑定（UDC 非空 = 激活中）
cat /sys/kernel/config/usb_gadget/tesla_usb/UDC

# 4. 分区挂上了
ls /mnt/teslacam/TeslaCam/
# 期望看到 RecentClips / SentryClips / SavedClips
```

然后浏览器打开 `http://<设备IP>:5000`，能看到仪表盘就成功了。

---

## 第 8 步：上车实测

Web 能开不代表车机认。最后一步必须上车：

1. 插到车机 USB 口（手套箱内的口，不是扶手箱纯充电口）
2. 车机屏幕出现行车记录仪图标
3. 等 5 分钟，看 `RecentClips` 有没有新文件
4. 锁车触发一次哨兵，确认企业微信收到推送

```bash
ls -lt /mnt/teslacam/TeslaCam/RecentClips/ | head -5
tail -50 /var/log/teslausb-sentry.log
```

---

## 常见卡点

| 现象 | 检查 |
|------|------|
| 车机认不出 U 盘 | UDC 是否为空、Gadget 是否绑定、分区是否 exFAT |
| Web 502 | venv 依赖是否装全、日志 `/var/log/teslausb.log` |
| 推送收不到 | `config/sentry.json` 的 Webhook 是否填对 |
| 服务起不来又秒退 | 八成是路径写死成了旧位置，见 [路径与配置项](../reference/路径与配置项.md) |

完整的排查流程见 [排障手册](../how-to/排障手册.md)。
