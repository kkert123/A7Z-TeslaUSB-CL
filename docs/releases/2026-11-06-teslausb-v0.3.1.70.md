## 二、变更内容

### 现象

从家里局域网（`12.127.12.122`）访问 A7Z 的「设置 → 安全」，修改任何参数均返回
**「安全配置仅限本地网络」**。审计日志连续 7 条：

```
security_denied · 12.127.12.122 · not_local_uninitialized
（11-05 08:18 / 22:39 / 22:40×2 / 11-06 00:09 / 09:36）
```

### 根因（真机取证）

| 检查项 | 实测 |
|---|---|
| `data/web_auth.json` | **不存在** → `load_config()` 走默认值 → `lan_cidrs = []` |
| 设备 `wlan0` | `12.127.12.115/24` |
| 客户端 | `12.127.12.122`（**同一 /24**） |
| `is_local_network()` | 仅 `127/8` ∪ `192.168.42.0/24` ∪ `lan_cidrs` |
| 结果 | 判「非本地」→ `_require_admin()` 未启用分支 → 403 `4007` |

**引导死锁**：要填网段，先得算本地网络；要算本地网络，又得先填好网段。
设计文档 §7.2 原文只给了一句「未配置局域网可能导致保存失败」的提示，没有引导路径
——**这是设计缺口，实现忠实照做了设计**。

### 修法（A + B，两处互补）

**A｜未启用阶段并入「设备自身直连网段」**（`utils/auth_service.py`）

- 新增 `direct_iface_cidrs()`：解析 `ip -4 -o addr show`，排除
  `lo` / `tailscale*` / `docker*` / `br-*` / `veth*` / `virbr*` / `tun*` / `tap*` / `wg*` / `zt*`；
  带 15 秒缓存；`ip` 不存在（Windows 开发机）时返回空列表。
- `is_local_network(ip, lan_cidrs, include_direct=None)`：
  - `None` → 自动：**未启用时**并入直连网段，已启用则严格只认手填网段；
  - `True` → 强制并入（测试用）；
  - `False` → 强制不并入（预判「启用后是否还有权限」）。
- 保留 tailnet 不算本地（D6 边界不变）。

**B｜启用前强制网段非空 + 前端预填**（`routes/auth_routes.py` / `templates/system.html`）

- `POST /api/security/enable`：`lan_cidrs` 为空时返回 `4012`，附明确指引。
- `GET /api/security/config`：新增 `suggested_cidrs`；前端在网段框为空且未启用时自动预填。
- `POST /api/security/lan/save`：口径 C 的「保存后是否失去权限」改用**严格口径**
  （`include_direct=False`）判定，并新增返回 `local_after_enable`；前端在
  `local_after_enable === false` 时给出红色横幅（原 `has_local_access` 语义保留）。

### 影响面

- 默认（未启用登录保护）状态：**只放宽了 `/api/security/*` 的本地判定**，其余端点行为不变。
- 已启用状态：判定逻辑与 v0.3.1.69 完全一致（严格口径）。
- 未改动：录像、清理、USB gadget、WiFi、云上传、TeslaMate。

## 四、回滚方案

### 方式 1：Web 一键回滚（推荐）

设备上 `/opt/radxa_data/teslausb-bak/teslausb-v0.3.1.69.tar.gz` 为升级前自动备份，
在「升级」页选择该备份重新安装即可（等同执行一次同构升级）。

### 方式 2：命令行回滚（SSH 可用时）

```bash
ssh radxa@100.116.18.42            # 走 tailscale ssh
cd /opt/radxa_data
sudo tar xzf teslausb-bak/teslausb-v0.3.1.69.tar.gz -C teslausb-v0.3.1.69/
sudo ln -sfn /opt/radxa_data/teslausb-v0.3.1.69 /opt/radxa_data/teslausb
sudo systemctl restart teslausb-web teslausb-sentry teslausb-bgpreview \
                    teslausb-usb-guard teslausb-kernel-log teslausb-fan
# ⚠ 禁止 systemctl restart teslausb-watchdog（M107：无 SIGTERM magic-close，会整机复位）
```

回滚后判据：`readlink -f /opt/radxa_data/teslausb` 指向 `v0.3.1.69`，
且 7 个服务 cwd 全部为 `v0.3.1.69`。

> 回滚**只影响代码**，`data/web_auth.json` 不动。若已在 v70 上保存过网段，
> 回滚到 v69 后该网段依然生效（v69 同样读 `lan_cidrs`），不会产生新的自锁。

## 六、遗留待决策（不变）

- **S1**：未启用登录保护的「首次配置窗口」内，局域网任何终端都能调 `/api/security/*`
  用自己邮箱完成闭环再 `enable`，把主人锁在门外。**本版未改变该暴露面**（属设计固有，
  见 M117），选项：a 安装令牌 / b 缩短配置窗口 / c 接受。详见设计文档 §14.9。
- **S2**：若将来加 nginx 反代，`remote_addr` 恒为 `127.0.0.1` → 本地限制全失效；
  届时必须改为「只信任来自反代 IP 的 XFF 最后一跳」+ 补 XFF 伪造测试。
