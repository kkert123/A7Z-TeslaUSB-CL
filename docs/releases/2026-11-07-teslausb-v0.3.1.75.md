## 一、问题

用户报告两件事：

1. 点「立即执行清理」后页面停在「正在执行清理」**6 分半**，像卡死（以前 1 分钟内完成）
2. 事后「清理历史」变成「⚠️ 清理历史加载失败」

## 二、根因（真机取证）

### 2.1 耗时：一个 O(n²)

日志时间线：

| 时刻 | 事件 |
|---|---|
| 10:23:25 | 第 1 次 `POST /api/cleanup/execute` 开始 |
| 10:23:26 → 10:29:34+ | 持续刷 `ERROR 删除文件失败 [Errno 2]`（全是缩略图） |
| 10:30:00 | `清理孤儿缩略图释放: 391.8 MB` + `400.2 MB`（两行＝跑了两次） |
| 10:30:01 | `=== 清理执行开始 ===` ×2（视频阶段） |
| 10:30:02 | `=== 清理完成: 删除 1607 个文件, 释放 39.6 GB ===`（两条） |

**视频删除只用 1 秒，395 秒全在删缩略图。**

`AutoCleaner._delete_file_safe()` 每成功删一个文件就执行
`if os.path.isdir(parent) and not os.listdir(parent)` —— `os.listdir` 要读**整个目录**。
缩略图全部平铺在同一目录 → 删 n 个 = n × O(n)。

真机微基准：`listdir(23341 项) = 16.91 ms`
`23341 × 16.91 ms = 395 s` == 实测 395 秒（**一分不差**）。

触发链（老代码被 v0.3.1.74 点燃）：

1. v74 的 `ensure_shared_thumbnails()` 把 7 个版本目录的缩略图合并 → 并集 **23,341 项**，
   其中 14,911 个 mtime > 7 天（对应的视频早已删除）
2. 装 v74 那次升级由 **v72 的旧代码**执行，旧 `copytree` 穿透 symlink 又复制成真实目录
3. 单次清理要面对约 **23,000 个孤儿**（以前每次几十个）→ n 从 10¹ 跳到 10⁴

### 2.2 报错：两份非原子写撞在一起

「假死」诱发现场二次点击，而按钮**真的被重新点亮了**：
`applyCleanupMode()` 在 else 分支无条件 `btn.disabled=false`，且它每 **30 秒**
被 `loadCleanupPolicies()` 调用一次。

两份清理并发 → 同批文件删两次（`[Errno 2]` 刷屏）+ 两个写者用
`open(w)+json.dump` 写同一个 `cleanup_history.json` → 截断在
**char 8200（= 8192 + 8，8KB 缓冲边界）** → 读接口 `json.load` 抛异常 → 500。

## 三、变更

### `auto_cleanup.py`
- 新增 `atomic_write_json()` / `load_cleanup_history()` / `append_cleanup_history()`
- 新增 `_dir_is_empty()`（`os.scandir` + `next()`，O(1)）/ `_prune_empty_parents()`（本轮缓存）
- `_delete_file_safe`：父目录回收走 O(1) 判定；新增 `except FileNotFoundError` → 记 `missing`，不再 ERROR
- `_save_cleanup_history` 委托原子实现
- 原子写临时文件前缀改 `.atomic-`，避开 `cleanup_temp_files` 的 `.tmp_` 规则

### `routes/cleanup_routes.py`
- `/api/cleanup/execute` 加**单飞锁**（threading.Lock + `/var/run/cleanup.lock` flock），
  在跑直接 **409 + `cleaning` + `elapsed_seconds`**；锁文件建不了时 fail-open 退化为线程锁
- 原实现原样拆到 `_cleanup_execute_impl()`，由薄壳 `try/finally` 保证释放
- `_save_cleanup_history` 委托原子实现，去掉裸 `except: pass`
- `api_cleanup_history` 走 `load_cleanup_history()`，返回 `history_reset`

### `templates/analytics.html`
- `_cleanupRunning` / `_cleanupTimer` 状态位
- `applyCleanupMode` 不再无条件解禁按钮
- 执行中每秒刷新「⚡ 执行中 Ns」，≥30s 提示「请勿重复点击/刷新」
- 处理 409「已在执行中」
- 历史损坏重建时给黄色提示
- **成功也刷新历史**（旧版只在失败分支刷新）

## 五、回滚方案

**方式 A（推荐，页面）**：登录 → 升级页选择 `v0.3.1.74`（历史版本仍在
`/opt/radxa_data/teslausb-v0.3.1.74`，且 `teslausb-bak/` 有压缩包）。

**方式 B（SSH）**：
```bash
sudo ln -sfn /opt/radxa_data/teslausb-v0.3.1.74 /opt/radxa_data/teslausb
sudo systemctl restart teslausb-web teslausb-sentry teslausb-bgpreview \
     teslausb-usb-guard teslausb-kernel-log teslausb-fan
sudo systemctl restart teslausb-watchdog
# 判据：逐个 readlink /proc/<pid>/cwd 都是 v0.3.1.74
```

回滚不影响数据：`data/` 与缩略图共享目录都不在版本目录里。

## 六、遗留
