## 二、现象与根因

用户截图反馈：设置页三个动作全部报错，一步都走不通。

| 操作 | 报错 | 直接原因 |
|---|---|---|
| 保存 SMTP | `4012 发送邮箱必须是完整邮箱地址` | **页面里 `id="sec-smtp-user"` 出现两次**（状态栏 `<b>` 在输入框之前），`getElementById` 取到 `<b>`，表单 `user` 恒为空串 |
| 测试发信 | `4012 请先填写安全邮箱` | 只读已保存的 `security_email`；前端没传界面值（**后端本来就支持 `security_email` 参数**） |
| 发送测试码 | `4006 请先填写发送邮箱与密码` | 只读已保存的 `smtp`；前端没传表单值 |

**P0（更严重，本次新发现）**：`start_email_change()` 生成 `code` 后调用的是 `_send_test()`
——那是一封「通道测试」邮件，**正文里没有验证码**。即使用户按正确顺序走完，收到信也填不出 6 位码，
安全邮箱永远无法完成闭环。等于该功能自上线起就没有真正可用过。

**结构性根因**：同一组配置存在两个真相源（已保存 config vs 界面当前值），
保存/测试/发码三者各自读不同的源，且「保存」因重复 id 读不到值 → 互相等待。

## 五、回滚方案

方式 1（推荐）：设备 `/opt/radxa_data/teslausb-bak/teslausb-v0.3.1.70.tar.gz` 为升级前自动备份，
在「升级」页选择该备份重新安装。

方式 2（SSH）：

```bash
ssh radxa@100.116.18.42
cd /opt/radxa_data
sudo tar xzf teslausb-bak/teslausb-v0.3.1.70.tar.gz -C teslausb-v0.3.1.70/
sudo ln -sfn /opt/radxa_data/teslausb-v0.3.1.70 /opt/radxa_data/teslausb
sudo systemctl restart teslausb-web teslausb-sentry teslausb-bgpreview \
                    teslausb-usb-guard teslausb-kernel-log teslausb-fan
# ⚠ 禁止 systemctl restart teslausb-watchdog（M107）
```

回滚判据：软链指向 `v0.3.1.70` 且 7 个服务 cwd 全为 `v0.3.1.70`。

## 六、正确的配置顺序（用户侧）

1. ① 发送邮箱：填 `system@...` + **16 位客户端专用密码** → 「保存 SMTP」
2. ② 安全邮箱：填**完整**地址 → 「发送测试码到新邮箱」→ 收信（标题「安全邮箱验证码 XXXXXX」）→ 回填 → 「确认并保存」
3. ③ 局域网网段 → 「保存网段」
4. ④ 本地密钥（只显示一次，务必保存）
5. ⑤ 「启用登录保护」
