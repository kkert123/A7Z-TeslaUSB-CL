## 二、证据：6 次真实锁车，漏 2 次

| 时刻 | 日志 | 判定 |
|---|---|---|
| 14:06:12 | 车态矛盾 → 按已锁 · **已发出** | ✅ |
| 15:06:12 | 车态矛盾 → 按已锁 · 无推送 | ✅ 正确（同一把锁，`locked` 漂移） |
| **16:31:12** | 车态矛盾 → 按已锁 · **无推送** | ❌ **漏**（15:36 已开走） |

| 19:36:15 | **已发出** | ✅ |

## 三、根因：闩锁只认 `locked=false`，而它一直报 true

`_lock_reported`（"这一把锁已报过"）的复位条件只有一处：

```python
if cur is False:
    self._lock_reported = False          # 只有真实解锁才复位
```

而 **TeslaMate 的 `locked` 会滞后**：14:06 锁车 → 开门上车 → 开走，它全程仍返回 `true`
（当天三次「`sentry_mode=true` 但 `locked=false`」的 WARNING 就是它漂移的指纹）。于是：

```
14:06 锁车 → 推送，闩锁 = True
15:36 开走 → locked 仍报 true → 走不到复位分支 → 闩锁还是 True
16:31 锁车 → "这一把已报过" → return，一条都不发
```

真正**铁证的"未锁"信号**（`speed>3` / `shift_state=D,R` / `state=driving`）当时只被用来
"挡住推送"，**不带复位**——等于看着证据不解锁。

**第二个原因（"立马"做不到）**：`config/guard.json` 实测 `states_interval_s = 300`，
车态快照 **5 分钟才拉一次**。判据再对，锁车后也可能等 5 分钟。

## 四、改法

| # | 改动 | 说明 |
|---|---|---|
| 1 | **闩锁复位前置** | `moving`（`D/R` 档 ∨ `speed>3` ∨ `state=driving`）判据提到闩锁判断**之前**，命中即 `_lock_reported=False`。这是本次的核心修复 |
| 2 | **复位留痕** | 复位时打 `锁车闩锁已复位（车在动：档位=D 车速=43）`，以后漏推能一眼看到卡在哪一步 |
| 3 | **采样两档自适应** | 新增 `states_fast_s=60`（还没确认锁好时用）/ `states_interval_s=300`（已锁并推过后放慢省流量）。锁车检测延迟 ≤60s |
| 4 | **冷却 600 → 120s** | 闩锁修准后，10 分钟冷却只会误伤「下车拿个东西又回来锁」 |
| 5 | 设置页新增「车态快采间隔」 | `states_fast_s` 进 `GUARD_EDITABLE` + limits `[20,300]`；「锁车报告冷却」提示语改为"纯防抖" |

### 现场时间线重放（修复后）

```
开机首拍（车未锁）
① 锁车（14:06 矛盾归一）      ★ 推送    闩锁=True
   停着（15:06 locked 漂移）   静默      闩锁=True
② 开走（locked 仍报 true）     静默      闩锁=False   ← 关键：这里松了
③ 锁车（16:31）               ★ 推送    闩锁=True    ← 旧版漏的第 1 次
④ 解锁（16:41）               静默      闩锁=False
⑤ 锁车（16:51）               ★ 推送    闩锁=True

共推送 3 条 = 3 次真实锁车（旧版只推 2 条）
```

同一把锁的重复上报仍然静默（不刷屏），防抖 120s 内的二次锁车仍被挡住且**不丢闩锁**（下一拍可补）。

## 七、部署后应有的行为

- **正常场景**：开车（60s 采样）→ 停车 → 锁车 → **≤60 秒**收到「停车自检」。
- **同一把锁**：停一晚也只推 1 条，不会因为 `locked` 漂移刷屏。
- **短途多次**：下车拿东西 <2 分钟又回来锁，防抖会挡（可把「锁车报告冷却」调到 120 下限以下不支持）。
- **没网锁车**：报告走 `critical` 落盘队列，回网/重启后补发，正文标注「补发 + 原生成时刻」。
- **排查口径**：日志里搜 `锁车闩锁已复位` 与 `停车自检已发出`，两者应一一对应。

## 八、影响面

- 只改 A 端判定与采样节奏，无数据迁移、无配置破坏性变更。
- `states_fast_s` 缺失时自动用默认 60s；配错（>慢档 / ≤0）自动退化慢档。
- 回滚：换回上一版目录即可。
