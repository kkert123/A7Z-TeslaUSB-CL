# v0.3.1.76 — 自检守护 A 端（心跳 + 自检快照）

> 日期：2026-11-07 ｜ 主题：新增 `guard_client.py`（停车自检守护的 A7Z 侧）
> 状态：**已发布**（2026-11-08 00:18）｜设备**未升级**（待授权）

## 1. 需求

A7Z 断网/崩溃/断电时，它自己发不出通知。原有的企业微信推送全部依赖"设备活着且能上网"，
所以"设备失联"这件事恰恰是**唯一无法由设备自己报告**的故障。

配套的 B 端（僚机）已于 2026-11-07 部署在腾讯云轻量 `vm-0-17-ubuntu-sh`
（Tailscale `100.111.252.121:8899`，只绑 TS 接口），负责「收心跳 → 判死 → 发告警」。
本次补齐 **A 端**：采集自检快照 + 定期心跳 + 预期离线握手。

设计文档：`docs/explanation/自检守护-B端VPS设计.md`（§3 契约 / §4 判据 / §5 A 端配合 / §14 实现落点）

## 2. 实现

**新增 `guard_client.py`（1060 行）**，由 `app.py` 在 `__main__` 块里以 daemon 线程拉起。

| 能力 | 说明 |
|---|---|
| 快照采集 | `net`（SSID/RSSI/Tailscale/exit_node/出网/TeslaMate）/ `gadget`（UDC state/mode/cable）/ `thumb`（服务/队列/阻断）/ `wechat`（推送健康）/ `vehicle`（`/states` 三态）/ `selfcheck`（四项 pass-warn-fail） |
| 落盘 | `data/guard_status.json`，原子写（mkstemp + `os.replace` + 目录 fsync） |
| 发送 | TS 优先 → HTTPS 兜底；8s/10s 超时；HTTPS 强制 `ca_path` pinning |
| 容错 | 双通道失败入队 `data/guard_queue.json`（上限 200），恢复后从队头补、每轮 ≤3 条 |
| 预期离线 | `state→driving` / `locked` True→False / `user_present` False→True 时握手；分档窗口（3600/900/600s）；失败重试 ≤3 次 |
| 反向探活 | 每 150s 一趟 HTTPS 探针 + `GET /guard/ping`（B 挂了 A 能知道） |
| 只读接口 | `GET /api/guard/status`（走登录守卫） |

**默认关闭**：`config/guard.json` 不存在或 `enabled=false` → 不建线程、不发请求、不写文件，
行为与 v0.3.1.75 等价（M116）。

## 3. 复核中发现并修掉的缺陷（4 P0 + 9 P1 + 5 P2）

| 级别 | 缺陷 | 后果 |
|---|---|---|
| P0 | `"enabled": "false"` 被 `bool()` 判成开启 | 用户以为关了，实际在发心跳 |
| P0 | `endpoints.https` 写成 `http://` 时 CA 校验静默失效 | Bearer token 明文过公网 |
| P0 | `expected_until` 用 A 的绝对墙钟、B 拿自己 now 比 | 钟差 2h → 漏报 3h / 当场误报 |
| P0 | 探针 600s > B 的 ALARM 300s（**设计 §2 与 §4 自相矛盾**） | TS 抖动被误报成「设备失联」，三条互相矛盾的消息 |
| P1 | `queue_max=0` → `items[-0:]` 全表 | 队列永不淘汰，写满分区 |
| P1 | 参数无上下限（timeout=0 永久入队、states=0 打爆 TeslaMate 配额） | 静默失效 |
| P1 | 探针最坏耗时叠加 > 心跳周期 | 节拍漂移，吃掉 B 的判据余量 |
| P1 | 探针返回 None 时判 pass | 自检「假绿」 |
| P1 | `usb_guard_status` 新鲜度未使用 | usb_guard 停摆后仍显示 configured |
| P1 | 状态接口不区分「活着」与「停摆」 | 状态页展示三天前的快照 |
| P1 | `last_sent_at` 失败也刷新 | 状态页把超时说成「刚刚成功」 |
| P1 | 发送失败只有 debug 日志 | 配置错到永远好不了也没人知道 |
| P1 | `going_offline` fire-and-forget | 这趟出车的防误报闸门丢失 |
| P1 | vehicle 缓存无 stale 判定 | 车开走后 B 仍按旧快照判「该在线」 |
| P2 | 补报在新鲜心跳之后 / 三种跃迁共用 1h 窗口 / `ping` 未实现 / `ExitNodeStatus` 字段名错 / `/proc/net/wireless` 误判已连接 / 读 `push_health.json` 撞非原子写 | 见设计文档 §14.6 |

B 端同步修：`judge.py` 优先相对量 `offline_s`、旧 `expected_until` 夹到 `[now+60, now+6h]`、
单通道部署不再误报「Tailscale 通道故障」。

## 5. 部署与回滚

**部署**：正常升级后，需在设备上**手工**创建 `config/guard.json`（不在升级包白名单，
避免升级覆盖 token），然后 `systemctl restart teslausb-web`。

**回滚**（30 秒，无需退版本）：
```bash
sudo rm -f /opt/radxa_data/teslausb/config/guard.json
sudo systemctl restart teslausb-web
```
`guard_client` 未启用时零行为，等同于 v0.3.1.75。
