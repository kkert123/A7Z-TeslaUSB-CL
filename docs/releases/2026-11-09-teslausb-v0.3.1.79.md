# v0.3.1.79 · 僚机卡片 UI 修复 + 企微自检假告警

> 日期：2026-11-09 ｜ 状态：**已发布** ｜ 配套：`guardian-b v1.1.2`（确认码自动推企微，独立部署）
> 上游：v0.3.1.78（僚机版本同步）

---

## 1. 这个版本解决什么

v78 把僚机升级搬进版本页之后，实际用了两次，暴露两类问题：**页面反馈不实时**，以及**自检长期假黄**。

| # | 现象 | 根因 |
|---|---|---|
| ① | 僚机状态文字全是灰色，看不出好坏 | `#peer-state` / `#peer-upg-state` 都继承 `var(--text-muted)`，只有圆点分了状态 |
| ② | 「还剩 600 秒」永远不动 | `confirm_expires_in` 是 B 返回的**一次性快照**，前端没有本地递减 |
| ③ | 点「预置」后状态不刷新 | `peerUpgrade` 的 `finally` 只调一次 `loadPeer()`，撞上 `busy` 就被丢弃，且 `pending` 标志可能没人消费 |
| ④ | 提示语还在教人去僚机捞日志 | B v1.1.2 起确认码已自动推企微 |
| ⑤ | 自检长期「注意」，`wechat` 项永远 `warn` | 判据读 `push_health.json`（旧 weixin_notifier 的地盘），而自检报告走 `guard_client._push_wecom`，成功只做内存计数、从不落盘 → `last_ok` 停在 172 天前（M130） |

## 2. 改了什么

### 2.1 前端（`templates/system.html`）

- **状态着色**：在线/已完成=绿、待确认=橙、切换中=蓝、连不上/失败/回滚=红、未配置=灰
- **本地倒计时**：`_peer.expAt = Date.now() + expires_in*1000`，每秒刷新 `#peer-exp`；≤60 秒变橙，归零显示「已过期 · 请重新预置」并**禁用确认按钮**
- **预置后短轮询**：`peerWatchState('verified')` 每 1.5 秒拉一次，最多 20 次，超时明确提示
- **文案适配**：B ≥ 1.1.2 且 `confirm_code` 为空时提示「已推送到企微」

### 2.2 后端（`guard_client.py`）

- 新增 `PUSH_HEALTH_OWN = data/guard_push_health.json`，`_note_push(ok, count=True)` 原子写入真实发送结果
- `_wechat_snapshot()` 优先读自己，回退旧文件（`source` 字段可区分）
- `_selfcheck()` 的 wechat 判据改为「最近一次尝试成功」；单次失败只在 30 分钟内算可疑（`WECHAT_FAIL_WARN_S`）；`bot_key_set=False` 判 warn（配置缺失 ≠ 通道故障）
- 「发送测试」也计入健康：用户点一次就能把自检从 warn 翻正

## 3. 双审查发现并修掉的问题

两个独立审查（前端 / 后端）共提出 2 条 P0、7 条 P1，**全部处理**：

| 级别 | 问题 | 修法 |
|---|---|---|
| P0 | 确认码过期后按钮被无条件放开（B 在过期时返回 `expires_in=0`，journal 仍是 verified）→ 用户必点必失败 | `disabled = !(expires_in > 0)` + 明确提示「已过期，请重新预置」 |
| P0 | 预置失败时按钮永久停在「推送并校验中…」且 disabled | `finally` 无条件复位文案与可点性 |
| P1 | 确认失败不刷新 → A 停在 `verified`，预置按钮被 `canUp` 永久锁死（死锁） | `finally` 里 `loadPeer()` |
| P1 | watch 与 `startPeerPoll` 双轮询互抢提示文案 | 离开待确认态即 `peerStopWatch()` |
| P1 | 早退分支不更新 `lastState` → watch 空转 20 次且静默 | 四处置空 + 超时提示 |
| P1 | `fetch` 无超时 → `busy` 永久为真，页面失去自愈 | `AbortSignal.timeout(12000)` |
| P1 | `busy` 分支的 `setTimeout` 兜底是死代码（JS 单线程下该竞态不存在），连点堆定时器 | 删除，只留 `pending = true` |
| P1 | `_note_push` 异常不安全，会污染 B 失联状态机（`_ping_ok` 里先发通知再清去重标记） | 整函数 try/except + `_num()` 安全转换 |
| P1 | 重试失败重复累加 streak → 一次 90 秒抖动就判 fail | `_note_push(False, count=False)` |
| P1 | 测试未隔离 `PUSH_HEALTH_OWN` → 真机上跑测试会覆盖生产健康记录 | 指到 `TMP/guard_push_health.json` |
