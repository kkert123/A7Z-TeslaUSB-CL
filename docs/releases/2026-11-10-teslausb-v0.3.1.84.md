# v0.3.1.84 — 升级/回退不再毁配置（原子替换 + 备份自检 + 回退必重启）

> 日期：2026-11-10 ｜ 状态：**待发布** ｜ 关联教训：**M139**

## 一、事故回顾（11-10 09:03）

升到 v0.3.1.83 后，A7Z 出现三件互相牵连的怪事：

1. 页面「僚机安全登录信息」变空、网络卡片显示「僚机 线程未运行」；
2. `journalctl` 里每 30 秒一条 `sqlite3.OperationalError: no such table: delete_queue`；
3. 回退到 82 后页面仍显示「当前 v0.3.1.83」，再点回退提示「当前已是 v0.3.1.82，无需回退」，
   点「重启服务」才认出 82。

根因（全部有 journal 证据）：

| # | 根因 | 证据 |
|---|---|---|
| ① | `_restore_user_data` 用 **`rmtree` + `copytree`** 替换 `config/`、`data/`，中间有「目录不存在」的窗口 | 09:03 进程报 `No such file: /opt/radxa_data/teslausb/config/sentry.json` |
| ② | 在线复制 **WAL 模式的 SQLite**（`.db` 与 `-wal` 分两个文件）→ 表只存在于 WAL 里就丢 | `no such table: delete_queue` |
| ③ | `_save_user_data` 整段 `except: pass`，`saved_cfg` 先赋值再 copytree → 失败留半份、恢复照单全收 | 无任何报错，升级显示成功 |
| ④ | 备份只落 `/tmp/upgrade-keep-*`，`finally` 删除；`_backup_current` 不校验 base 目录 | 09:08 产出 `teslausb-vteslausb.tar.gz`，**8994 B** |
| ⑤ | `do_rollback` 只切软链**不重启**，前端却承诺「并重启服务」 | 页面「当前 v83」+ 提示「已是 v82」 |
| ⑥ | 软链切换对「真实目录」直接 `rmtree` | 该设备一度是扁平布局，日志里能看到目录被整体替换 |

## 二、改了什么

### 1. 原子替换（消灭"配置消失窗口"）

```python
_copy_dir_atomic(src, dest, tag):
    copytree(src → dest.new-<ts>)   # 先拷到旁边
    _assert_copied(src, new)        # 拷完校验（缺一个文件就抛错）
    rename(dest → dest.old-<ts>)    # 旧目录改名保留，不删
    rename(new → dest)              # 同目录 rename 原子顶上
```

读侧要么看到旧的、要么看到新的，**不存在"目录不存在"的瞬间**；旧目录留一份（`.old-*`，只保留最新一个）可人工回捞。

### 2. SQLite 一致性

- 保存前对 `data/*.db` 执行 `PRAGMA wal_checkpoint(FULL)`，尽量把 WAL 落回主库；
- 复制后对每个 `.db` 做 `PRAGMA quick_check`，**不通过就用 `VACUUM INTO` 从源库重新导一份一致快照**；
- 仍不通过 → 抛错中止（不再带着坏库继续升级）。

### 3. 失败一律 fail-loud

- `_save_user_data` 失败抛 `UserDataError`（临时目录同时清理），调用方**在切软链之前中止**并回一句人话；
- `_restore_user_data` 失败同样中止，且 `rmtree(new_dir)` 收尾——此时 `current` 还没动，现有版本完全不受影响；
- 备份失败**不再"警告后继续"**：没有备份就没有退路，宁可这次不升。

### 4. 备份自检

`_backup_current` 三道校验：base 必须是**真实版本目录**（`realpath` + 版本号正则）、包内必须含 `app.py` + `config/`、体积 ≥ 200 KB。任一不满足直接拒绝升级。

### 5. 回退必须重启 + 混合态可见

- `/api/version/rollback` 成功后调用 `_schedule_restart()`，返回「已回退到 vX，正在重启服务…」；
- `/api/version/check` 新增 `running_version` / `disk_version` / `mixed`；
- 页面在版本卡片下方显示橙色条：**「运行中 v83，磁盘上是 v82（回退/升级后未重启）」+ 一键重启按钮**，不再让人对着两个互相矛盾的版本号猜。

### 6. 软链切换拒绝"真实目录"布局

`_switch_symlink` 遇到真实目录直接报错（`请先手工迁移成软链`），不再 `rmtree` 整个部署。

## 五、升级注意

本次安装仍由**旧的 0.3.1.82 升级代码**执行（新逻辑从下一次升级才生效）。
安装前建议手工留一份配置备份：

```bash
sudo cp -a /opt/radxa_data/teslausb/config /opt/radxa_data/config.bak-$(date +%m%d-%H%M)
sudo cp -a /opt/radxa_data/teslausb/data   /opt/radxa_data/data.bak-$(date +%m%d-%H%M)
```

## 六、回滚

```bash
sudo bash -c 'ln -sfn /opt/radxa_data/teslausb-v0.3.1.83 /opt/radxa_data/teslausb && systemctl restart teslausb-web'
```
（v0.3.1.84 起页面回退也会自动重启，无需手工。）
