# v0.3.1.87 — 推送标明来源（A7Z / 僚机）+ WiFi 名称完整显示

> 日期：2026-11-11 ｜ 状态：**待发布** ｜ 关联教训：**M143**
> 配套：**guardian-b v1.1.6**（B 端所有标题同步改成 `【僚机】` 开头）

## 一、用户反馈

> 1. 推送过来的信息没有区分是 A7Z 发的还是僚机发的
> 2. WiFi 名称显示不全

截图里的实际内容：`网络  正常 YL-MIFI-…`（被截断），标题 `【停车自检】✅ 正常`（没标来源）。

## 二、根因

**① 来源分不清——A 和 B 共用同一个企微机器人。**
`wecom_guard_webhook_key` 双持有（A `config/sentry.json` + B `data/runtime.json`），
手机里发送方名字都显示「A7Z守护」。**渠道层面没有区分能力，只能靠正文**，而原来的正文没标。

更严重的是语义不一致：B 端发的告警标题写的是 `【A7Z】设备失联` ——
设备失联时 A 已经死了，它根本发不出来，这条只能由 B 发，但标题让人以为是设备自己报的。

**② SSID 被截成 9 列。**
原实现把 SSID 塞进「网络」那一行并 `_clip(ssid, 9)`：

- 不截：`网络   正常 YL-MIFI-000500` = 31 列，必折行（M140 刚修过的问题）
- 截断：`YL-MIFI-…` —— 恰好把「是家宽还是车载热点」这个关键信息砍掉了

## 三、改法

### 规则：方括号里永远是「发送方」

| 发送方 | 标题 |
|---|---|
| A7Z | `【A7Z】停车自检 ✅正常` |
| A7Z | `【A7Z】正常 → 注意` / `【A7Z】已恢复正常` / `【A7Z】自检日报 正常`（原有，未变） |
| 僚机 | `【僚机】停车自检 代发` |
| 僚机 | `【僚机】A7Z 失联` |
| 僚机 | `【僚机】TS 通道故障` |
| 僚机 | `【僚机】A7Z 已恢复` |

标题宽度：`【A7Z】停车自检 ✅正常` 是 22 列（emoji 与档位之间不留空格，留了就是 23 列会折）。

### SSID 单独一行

```
【A7Z】停车自检 ✅正常
已锁（据哨兵）
停车 00:00 · 电量 89%
网络   正常
USB    正常 已连接
缩略图 正常 积压1
推送   正常
WiFi   YL-MIFI-000500      ← 独立行，15 列以内完整显示
v0.3.1.87 · 19:05
```

`WiFi` 用 7 列标签宽度对齐其余分项；超过 15 列才截断（`WiFi-YL-MIFI-000500` 这种超长 SSID 会截成 `WiFi-YL-MIFI-0…`，仍然可辨认前缀）。

### 顺带修两个连带缺陷

| 问题 | 现象 | 修法 |
|---|---|---|
| 网络异常时行尾空白 | Tailscale 掉线但 `internet_ok=True` → 只剩一个 `❗ 网络`，没说原因 | 非 pass 时依次判：`出网不通` / `TS 未运行`（新增 `_TS_CN` 中文化）/ `链路异常` |
| 异常行被截断 | `⚠ 缩略图 积压128·15秒前` = 24 列 → 截成 `积压128·15秒…` | 去掉「前」正好 22 列，语义由同行的「积压」兜住 |
