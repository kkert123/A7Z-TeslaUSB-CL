## 二、问题与根因（真机实测）

起点：根分区 `/dev/mmcblk0p3` 28G，已用 25G，**仅剩 2.7G（91%）**。

| # | 根因 | 证据 | 占用 |
|---|---|---|---|
| 1 | 每个版本目录各带一份 `static/thumbnails` | 单份 1.81G / 14836 个文件；7 个历史版本 | ≈11.4G |
| 2 | `/tmp/upgrade-keep-*` 从不删除 | `_save_user_data()` 用 `mkdtemp` 建备份，`_restore_user_data()` 只复制出来，**无配对 rmtree** | 5.5G（3 份） |
| 3 | journald 无上限 | `journalctl --disk-usage` = 2.7G；`/etc/systemd/journald.conf` 的 `SystemMaxUse` 仍是注释 | 2.7G |

结构性问题：**运行期缓存放在版本化的代码目录里** → 每次升级都整份复制、旧目录又不删，随版本数线性翻倍。

## 三、变更内容

| 需求 | 实现 | 位置 |
|---|---|---|
| 1. 临时目录 finally 清理，不改 `/tmp` 用途 | `_save_user_data()` 改返回 `(tmpd, cfg, data, thumbs)`；`do_upgrade` / `do_upgrade_from_tarball` 拆为「包装 + `_do_upgrade_impl` / `_do_upgrade_from_tarball_impl`」，包装层 `try: … finally: _release_keep_tmp(ctx)` | `upgrade_service.py` |
| 2. 版本目录只留最近 5 个 | `prune_version_dirs(keep=VERSION_DIR_KEEP=5)`；`BAK_KEEP` 10→5（备份压缩包同样留 5） | 同上 |
| 3. journald 限 1G | 新增 `ops/journald-limit.sh`（幂等写 `SystemMaxUse` + `journalctl --vacuum-size`，带 `--check`） | `ops/` |
| 4. 缩略图统一到共享目录 + 各版本 symlink | `ensure_shared_thumbnails()`；`_save_user_data` / `_restore_user_data` 遇 symlink 只复制链接本身 | `upgrade_service.py` |
| 收尾 | `_post_upgrade_storage()`：缩略图共享 → 版本剪枝 → 清理超龄 `upgrade-keep-*`（<5 分钟保留） | 同上 |

### 安全护栏（删除/迁移不误伤）

1. 只处理名字**严格匹配** `^teslausb-v(\d+)\.(\d+)\.(\d+)(?:\.(\d+))?$` 的**真实目录**
2. `shared` / `teslausb` / `teslausb-bak` / `teslausb-backups` 列入永不清理名单；`tim`、`teslausb-web`、`vmanual-upload` 因不匹配正则天然免疫
3. 符号链接一律跳过（避免删到共享目录本体）
4. `SYMLINK` 当前指向的目录 + 调用方 `protect` 列表永不删除
5. 删除前校验 `os.path.dirname(os.path.realpath(path)) == realpath(DEPLOY_BASE)`，防 `../` 穿越
6. `keep <= 0` 直接不动作（防误配置成「全删」）
7. 缩略图迁移：目标已存在同名文件**跳过不覆盖**，只补缺失项，再删源目录去重

## 四、执行顺序与生效条件

### 4.1 本次在设备上的执行顺序（已执行完毕）

| 步骤 | 动作 | 前置条件 | 释放 |
|---|---|---|---|
| 1 | journald 限 1G（`ops/journald-limit.sh 1G`） | 需要 root；会重启 `systemd-journald`（不影响业务服务） | ≈1.7G |
| 2 | 清理 `/tmp/upgrade-keep-*` | 确认无进行中的升级（年龄 > 5 分钟的才删） | 5.5G |
| 3 | 缩略图迁移（逐版本 `ensure_shared_thumbnails`） | 同文件系统（`os.replace` 才会瞬时）；运行中服务会在毫秒级窗口内可能 404 | ≈7.2G |
| 4 | 版本目录剪枝（`prune_version_dirs(keep=5)`） | 当前运行版本一定被保护；执行前确认回滚版本已选定 | ≈3.5G |

结果：`/` 已用 **25G → 9.2G**，可用 **2.7G → 18G（35%）**。
`/opt/radxa_data` **11.8G → 3.3G**；各版本目录由 1.86G 降至约 46MB；
缩略图合并为唯一一份 `shared/thumbnails`（23308 个文件 / 2.8G）。

### 4.2 后续自动执行（随本版代码生效）

- 触发点：**每次升级成功**，在切 symlink 之后、返回之前调用 `_post_upgrade_storage()`
- 顺序固定为：缩略图共享 → 版本目录剪枝 → 遗留临时目录清理
- 每一步都有独立 `try/except`，**任一步失败都不阻断升级**

### 4.3 生效条件

- 清理/共享逻辑属代码，**下一次升级**（含本版自身）开始自动执行
- journald 是设备侧 systemd 配置，已落 `/etc/systemd/journald.conf`，重启后仍有效（原文件备份为 `.orig`）
- 手工治理已做完，无需重复执行

## 六、回滚

代码回滚到 v0.3.1.72/73 不影响本次治理结果：

```bash
sudo ln -sfn /opt/radxa_data/teslausb-v0.3.1.72 /opt/radxa_data/teslausb
sudo systemctl restart teslausb-web teslausb-sentry teslausb-bgpreview \
                    teslausb-usb-guard teslausb-kernel-log teslausb-fan teslausb-watchdog
```

旧版本目录里的 `static/thumbnails` 已是指向共享目录的 symlink，
旧代码 `os.path.isdir()` 会跟随链接，**照常读写**，不需要回滚数据。
