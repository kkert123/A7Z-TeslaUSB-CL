# v0.3.1.88 — 僚机版本回退 + 「检查版本」不再被 6 小时缓存挡住

> 日期：2026-11-11 ｜ 状态：**待发布** ｜ 关联教训：**M144**（版本检测缓存）、**M145**（僚机回退）
> 配套：**guardian-b v1.1.7**（回退接口 + root helper 回退分支）

## 一、用户反馈

> 1. 在版本管理中僚机也没有版本回退（功能）按键。
> 2. 每次都是在"新版本更新说明"里先看到新版，然后要点击"重启服务"，再按"检查版本"才能检查到新版本。

## 二、问题 2：6 小时缓存吃掉了「检查版本」

```python
CHECK_INTERVAL = 21600        # 成功缓存 6h
MIN_REQUEST_INTERVAL = 600    # 距上次请求 <10min 一律用缓存
```

`checkVersionNow()` 请求 `/api/version/check` **不带 force** → 6 小时内点多少次都是内存缓存。
而「重启服务」把进程里的 `_version_last_check` 清零了 —— 这正是"必须重启才检查得到"的真相。

修法：

| 层 | 改动 |
|---|---|
| `version_service.py` | 新增 `FORCE_MIN_INTERVAL = 30`：`force` 绕过 6h/10min 缓存，但 30 秒内重复点复用缓存（保护 GitHub 匿名配额） |
| `routes/system_routes.py` | `?force=1` → `check_latest_release(force=True)` |
| `system.html` | 「检查版本」按钮改为 `/api/version/check?force=1` |

## 三、问题 1：僚机补上版本回退

原先 B 端只有「升级失败自动回滚」，**没有用户主动回退**的入口。

| 层 | 改动 |
|---|---|
| B `app.py` | 新增 `list_releases()`（扫 `releases/`，降序，标 `ok`）、`GET /guard/releases`、`POST /guard/rollback` |
| B `deploy/apply.py` | 新增 `do_rollback()`：切软链 → 重启 → 健康检查，**失败自动切回原版本**；判据严格 `state == "rollback"`，升级路径零改动 |
| A `guard_client.py` | `peer_list_releases()` / `peer_rollback()`（只转发，不判断） |
| A 路由 | `/api/guard/peer/releases`、`/api/guard/peer/rollback` |
| A 页面 | 僚机卡片新增「回退到 [下拉] [回退]」，仅在本地有 ≥2 个可运行版本时出现，二次确认弹窗 |

### 几个刻意不做的取舍

- **回退失败必须切回去**：退过去跑不起来等于守护没了，比不回退严重得多
- **回退后不调 `prune`**：刚离开的版本留着，可能马上要退回来（本地保留 3 个）
- **不动 `.trusted/floor`**：那是「不许降级到有漏洞版本」的安全下限，运维回退不该把它调低
- **校验全在 B 端做**：A 只转达，避免「A 说可以、B 拒绝」两套判据打架
- **升级进行中（committed/prepared/verified）一律 409**：两条流程不能同时改 `current`

### ⚠️ 部署时必须手工换 `apply.py`

`apply.py` 属于 `/opt/guard-b/.tools/`（**不在升级包内**——它能写 `/opt/guard-b`，被包覆盖等于提权）。
只升 B 包不换 helper 的话，回退请求会被接受但**什么都不发生**。

所以 B 端加了一道进门检查：`/guard/rollback` 先 grep `.tools/apply.py` 里有没有 `def do_rollback(`，
没有就返回 **501 `helper_too_old`**，绝不静默成功。

## 五、升级顺序

1. **先换 helper**（关键，否则回退不可用）：
   ```
   sudo install -m 0500 -o root -g root /tmp/apply.py /opt/guard-b/.tools/apply.py
   ```
2. **B 预置**：A 页面 → 僚机版本 → 上传 `guardian-b-v1.1.7.tar.gz` → 预置 → 企微确认码 → 确认
3. **A 升级**：Web 页点升级到 v0.3.1.88

## 六、影响面

- A 端：只改版本检测的缓存路径与僚机卡片 UI，无数据迁移
- B 端：新增只读接口 + 一个独立分支；`state == "committed"` 的升级路径逐字节不变
- 回滚：换回上一版目录 + 换回旧 `apply.py` 即可
