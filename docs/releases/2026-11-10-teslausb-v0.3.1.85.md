# v0.3.1.85 — 推送文案改窄排版（企微手机端不再折行）

> 日期：2026-11-10 ｜ 状态：**未单独发版，并入 v0.3.1.86 一起发布**
> 关联教训：**M140**
> 配套：**guardian-b v1.1.5**（B 端代发与告警文案同步改窄）

## 一、为什么改

用户贴来的实际推送截图：一条 8 行的停车自检，在企微手机端被折成 **14 行碎块**——

```
【停车自检】✅ 正常 · 车辆          ← 折
已锁（重启后补报）
车辆   停车 03:49 · 电量            ← 折
61%
网络   正常（C12345 · 出网          ← 折
正常 · TS Running）
```

根因不是"字多了"，而是**宽度没有责任主体**：标题、车态、分项证据、设备行分别由 4 个函数
拼出，每处都按"桌面宽度"写（27 / 31 / 33 / 45 列），而手机气泡约 **26~28 显示列就折行**。
任何一处加了字段、或变量变长（WiFi SSID `WiFi-YL-MIFI-000500` 单项就 19 列），整行立刻溢出。

## 二、改法

**统一的宽度约束（渲染末端）**

| 件 | 作用 |
|---|---|
| `_LINE_MAX = 22` | 折行点 26~28 留 5~6 列余量，也吸收 emoji 宽度误差 |
| `_disp_width()` | 中文算 2 列、ASCII 算 1 列 |
| `_fit(text)` | **每条消息最终输出处**兜底：先按 ` · ` 丢尾段，再不行才截断 |
| `_wrap(text)` | 判据类信息**只换行不删段**（`在开 43km/h · 已锁` 每段都是证据） |
| `_clip(text, w)` | 长变量截断（SSID / mode / 错误串） |

**结构上的减法**（比压字更有效）

- 标题只留「图标 + 档位」：`【停车自检】✅ 正常`（原 `… · 车辆已锁（重启后补报）`）
- 「已锁」单独一行，推断来源进同一括号：`已锁（据哨兵·补报）`
- 车辆行拆两行：`停车 03:49 · 电量 61%`（秒去掉）
- 分项标签缩短并对齐 7 列：`网络 / USB / 缩略图 / 推送`
- 证据去括号、只留最关键一条：`网络   正常 C12345`、`USB    正常 已连接`
- 异常时正常项压成一行：`其余 3 项正常`
- 设备行去掉僚机地址：`v0.3.1.85 · 12:41`（原 33 列；地址几乎不变，要看去设置页）

**同一轮把另外四条消息一起改**（否则同一套装备格式自相矛盾）：
跃迁 `【A7Z】正常 → 注意`、恢复 `【A7Z】已恢复正常`、日报 `【A7Z】自检日报 正常`、
B 失联 `【护卫告警】僚机失联`、B 恢复 `【护卫恢复】已连通`。
