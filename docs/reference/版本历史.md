## v0.3.1.59 · 2026-10-02（**已发布** Release ID 401885529 / tag→`df49b4a`）

- **修复「AP 模式下点『关闭AP』无效 / 前端报『请求失败』」（10-01 事故，M85）**：三条并行根因——① `stop_ap()` 关掉 AP 后无任何抑制 → 2min 一次的 `wifi-quick-check.timer` 下一轮把 AP 自动开回（用户看到的「没反应」= 关掉又被开回）；② 前端 `apAction('stop')` 的 `fetch` 走的就是它自己要拆掉的 AP 链路 → 必然 `Failed to fetch`（真成功被渲染成失败）；③ `_ap_bring_down()` 的「wlan0 是否重连成功」被当成「AP 是否已关闭」的判据 → 无网可连时误报失败
- 修复落地：新增持久抑制标记 `/var/run/teslausb-ap-manual-off`（`ts`/`ttl`，用户确认 **30min**）→ 所有自动开 AP 入口统一读它；**先写标记再关 AP，失败回滚**；新增 `_ap_transition_active()` 过渡闸（TTL 120s）防起停中 timer 抢开；`stop_ap()` 前置**幂等守卫**（AP 本就没开则什么都不做，不碰网络、不写抑制）；前端改为「先查状态 → 按 apOn 给文案」+ `AbortController` 3s 超时 + `warning`（AP 已关但没网）分支不 reload
- **抑制期提醒（A3）**：`SystemMonitor.check_ap_manual_off()` 进入抑制时推一条企业微信提醒（不踢客户端），推送前二次校验 `hostapd` 未运行防标记残留误报；**去重按标记而非时间窗口**（跨进程/跨重启有效，且不误吞「关→开→再关」的第二次合法提醒，M86）
- **RTC 回写（D1，事故 F1 取证项）**：新增 `rtc_sync.py` + `teslausb-rtc-sync.service/timer`（开机 3min 首跑，此后 30min）。A7Z 的 sunxi-rtc 掉电不保时 → 冷启动内核把时钟设到 1970 → journald 归档按错误时间戳排序、关键取证窗口被优先轮转删除（实测 09-29/09-30 各仅剩 2 行）。脚本只在 `NTPSynchronized=yes` 且年份 ≥2025 时回写，其余轮次跳过（零副作用）
- **WiFi 业务持久日志（D2）**：新增 `/var/log/teslausb-wifi.log`（`wifi_service` + `WifiSmartSwitch` 双 logger 落盘，plain `FileHandler`，轮转交 `log_rotator`）。修复「跨进程/跨重启排查 WiFi 问题时无日志可查」——`wifi-quick-check` 每 2min 新进程，原仅 `StandardOutput=journal`，滚动后无痕
- **已验证**：本地 + 设备端（Python 3.9.2）回归 **57/57 PASS**；设备实测 `teslausb-rtc-sync.timer` enabled+active、01:24:54 首次回写成功；`/var/log/teslausb-wifi.log` 已收到 2min timer 进程日志（证明持久 handler 跨进程生效）
- **已发布**：commit `df49b4a`（15 文件，+643/−8）→ Release **ID 401885529**（assets：`teslausb-v0.3.1.59.tar.gz` 522712 B / `.sig` 294 B）。三方核对全绿：tag→`df49b4a`（==push HEAD，M61）｜asset digest `sha256:652cd740edcc…` == 本地 == body（M72）｜body SHA256 行正则通过（M76）；远端资产下载后重算 sha256 一致、`ssh-keygen -Y verify` 端到端验签通过（模拟设备升级路径）。**发布脚本 `_release59.py` 首跑因 PAT 失效（401）中断，换新 PAT 后成功——教训 M88**

## v0.3.1.58 · 2026-09-26（并入 v0.3.1.57 内容）

- **USB 链路守护新增 L2.5 阶梯：平台驱动重绑**（`/sys/bus/platform/drivers/sunxi-plat-dwc3` 的 unbind/bind `12.usbc2`）。故障实证显示卡死在 USB2 复合体**父设备层**（`xhci-hcd remove, state 4` + USB bus 重注册），L1 soft_connect / L2 重跑 gadget 均不触发控制器 re-probe → 无效；L2.5 是「软件等价物理插拔」（M82）
- L3 兜底阈值 90s → **150s**；L2.5 `confirm_l25_seconds=60`，`allow_platform_rebind` **默认关闭**（门控优先于 DRY-RUN，关闭时零 sysfs 写），真机验证后再开
- **新增持久化内核日志采集** `teslausb-kernel-log.service`（`kernel_log_capture.py` 直采 `/dev/kmsg`，落盘 `data/kernel_live.log` 5MB×2 轮转，绕开 journald 归档盲区，M83）；`upgrade_service.startup_self_heal()` 增加其幂等安装钩子（M45/M75）
- **AP 模式手动切换 WiFi 失效修复**（M81）：入口先让出 AP（`force-on` 拒绝）→ 失败必兜底重开 AP；AP 让出后沉降等待改为「目标 SSID 出现 或 ≥8s 下限」（修复「非空旧缓存即返回」）；`_wlan0_has_ip` 排除 AP 子网 IP（防误判已有 IP → 跳过兜底）
- 同时并入 v0.3.1.57：USB 守护独立化 `teslausb-usb-guard`（M80）、升级标记两路都写（M77）、开机推送（M78）、模板 textarea 自适应（M79）
