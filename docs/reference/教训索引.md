| M60 | **签名与凭据两个发布阻塞点（9-5 实证）**：① `upgrade_key` 是 OpenSSH Ed25519 私钥，签名必须 `ssh-keygen -Y sign -f upgrade_key -n file`（SSHSIG），`openssl dgst -sign` 直接报错——《发布新版本》文档曾写错，已修正；② PAT 会过期/被吊销（9-3 可用、9-5 401）：Release 401 Bad credentials 时先用 `GET /user` 验 token，再查代理 |
| M61 | **Release 必须显式指定 `target_commitish`（9-5 实证）**：仓库默认分支 `main` 与实际开发分支 `master` 分叉（main 停在 7-25），API 建 release 不指定 target 时 tag 打在默认分支 HEAD → 指向旧提交，且 `/releases` 列表按 tag 日期排序，新 release「消失」在列表后段。幂等检查要查 tag 本身（`GET /git/ref/tags/`，仅查 release 不够——旧 tag 会让新 release 挂上去）。发版后核对：tag sha == push 的 HEAD |
| M62 | **第三方服务端响应结构会静默变更（9-5 实证）**：TeslaMate 自定义服务升级后 `/msg` 不再下发 `ui_current_address`，且 `location` 从 dict 变 JSON 字符串 → 下游解析静默失效，兜底路径刷出误导性的「认证失败」日志（认证其实一直成功）。① 解析外部接口必须容错（字段缺失/类型漂移/`"nil"` 字符串）；② 200 但缺预期键时打 warning 带实际键名；③ 日志措辞要与真实失败点一致，别让下游失败冒充上游故障；④ 调试期复用缓存凭据，别反复全新登录触发服务端推送骚扰 |
| M63 | **外部 API 匿名配额要按「设计余量」对待（9-5 实证）**：版本检测匿名调 GitHub（60/h 按出口 IP，与局域网设备共享），失败不缓存 + 页面 30s 轮询 = 持续 403。① 降频留余量（6h 间隔 = 0.3% 配额）；② 失败也设 TTL 缓存防轮询轰炸；③ 读响应头余量做硬护栏（force 也不例外）；④ 白名单文件必须 git 跟踪（version_service.py 曾一直未入库——M36 不是一次性的） |
| M64 | **缩略图「货不对板」完整机制与防御（9-5 实证）**：Tesla 循环回收 RecentClips 文件名，VFS 正缓存（文件名→旧簇）不随回收失效 → ffmpeg 抽到旧簇帧（同机位白天画面混入夜间事件）→ 四宫格单格错图且 ≥10KB 被永久缓存。ensure_fresh 30s TTL 节流留有缝隙。防御：**生成后自校验**——用 mvhd 录制时间 vs event_id（偏差 >300s 判错，容错 mvhd 缺失），不符 → ensure_fresh(force=True) 强制刷重试一次，仍不符则放弃本次生成（宁缺毋假，不落盘）；ensure_fresh 需提供 force 参数绕过 TTL |
| M65 | **部署器对 root 属主目录写入新文件会静默失败（9-5 实证）**：deploy_manager 以 radxa 身份 sftp 写入，旧文件可覆盖、新文件 EACCES → 代码已引用新模块而文件缺失 → web 持续 ImportError。① 部署输出被 tail 截断时错误行不可见，部署后必须核对每个目标文件存在；② 修复：sudo 写入或升级流程（upgrade_service 以 root 解包）带入；③ 新增文件务必随升级包分发并在部署后做 import 自检 |
| M66 | **缩略图 N/A 缺格与「生成即质检」（9-5/9-6 实证）**：扫描读到的 mtime 是冻结页缓存旧值 → 误判写入已停提前生成，此刻后摄 mp4 仍在写入未封口 → ffmpeg 抽帧失败 → N/A 缺格，且缩略图已存在被永久跳过。防御：生成后校验「有视频文件的摄像头必须有帧」+ mvhd 时间匹配（M64），任一不过 → ensure_fresh(force) 重试一次 → 仍不过放弃不落盘（宁缺毋假），下轮扫描自然重试补齐。**同现象可能多根因**（旧簇串图 / 缺格 / 镜像），取证比对后再定修复 |
| M67 | **SSE stats 新增顶层字段必须同步两处摊平点（9-6 实证）**：仪表盘实时流有两条数据装配路径——SSE 首帧（system_routes stats-stream）+ broadcaster 周期帧（app_helpers），两者各自维护「顶层摊平清单」（nvme_total_disk/monthly_traffic/gpu_npu…）。新增 stats 字段只改 get_system_stats 不够，漏摊平 → 前端 `d.字段` undefined 且无报错（元素 display:none 静默不显示）。修复后用 curl 抓 SSE 首个 data 帧验证字段在顶层 |
| M68 | **oneshot 硬件初始化脚本必须可重入（9-6 实证）**：teslausb-mode（oneshot，Present 模式）重跑 usb_gadget_init.sh 时 UDC 已被上次运行的 gadget 占用 → `echo UDC > UDC` EBUSY → 服务 failed 且每次 restart 同样失败（无 Restart= 自动重试），而 gadget 实际仍在正常工作（UDC=configured）——服务状态与实况脱节。防御：绑定前检测 UDC 非空先解绑（`echo "" > UDC`）+ sleep 1，脚本可任意次重复执行；同类硬件初始化（挂载/接口/LED）都应先释放再申请 |
| M69 | **「推送断断续续」三因叠加与取证方法（9-6/9-7 实证）**：① WiFi 检测服务 `_get_current_ssid` 方法1 返回 NM 连接名而非 SSID（profile 名 WiFi-YL-MIFI-000500 ≠ SSID），同网跳过失效 + 优先级比较出 0 vs 150 幻觉 → 每 10 分钟对同一 SSID 断开重连（单日 31 次）；② 车载热点（无外网）在家可达且页面优先级最高（600），被 NM 自动选中 → 直播推送全败、仅重试队列在切回家 WiFi 的窗口零星成功；③ 重试队列 10 次/50 分钟耗尽即永久丢弃。防御：连接名→SSID 解析、优先级读页面权威值（多 profile 取 max）、位置判定落盘供独立进程共享 + 在家白名单门控、推送 10/30/60 退避、队列耗尽转每小时慢试 48 次才弃。取证关键：单事件「检测→推送」时间线逐条比对；关键词过滤会漏掉成功路径与自匹配噪音 |
| M70 | **「生成即质检」必须按目录语义设计，否则变成误杀机器（9-7 实证）**：v45 的 mvhd 串图校验拿「任一切片与事件名偏差 >300s」判定，但 SentryClips 事件文件夹天然包含触发前 ~11 分钟预缓冲切片（实测 -613s）→ 当天所有较长哨兵事件缩略图被误杀；被回收的 REC 分钟目录仍在无限重试，每轮 force drop_caches 单日 760 次 → I/O 风暴（TeslaMate/systemctl 连带超时）。防御：① 校验按目录类型区分语义——mvhd 校验仅限会被回收复用的 RecentClips；② 放弃时检测目录/前缀文件是否已消失，消失即入阻止列表（REC 平铺结构要按「event_id-*.mp4」前缀匹配，不能用 folder_path——那是基础目录恒存在）；③ force drop_caches 全局限流 60s；④ 缺格检测用目录实时列表而非抽帧前快照。另：队列 status=failed 的条目 scan 会因 seen_ids 不再入队——批量补救要清 failed 条目并重启服务 |

## 内核 / 挂载 / 缓存

| ID | 教训 |
|----|------|
| M52 | Present 模式「stat 目录 mtime」被 VFS inode 缓存冻结，感知不到特斯拉写入。检测必须用 listdir 指纹（dentry miss 强制读盘）。**涉及内核缓存/挂载行为的逻辑必须真机验证，纯代码审查抓不到** |
| M53 | `systemctl restart NetworkManager` 打断 systemd-resolved 的 D-Bus → resolved 崩溃 → `Restart=always` + start-limit 限流 → 本机 DNS 永久损坏。恢复网络用 `nmcli device connect wlan0` 局部重连 |
| M58 | **M52 修正（v0.3.1.41，9-3 实证）：readdir 目录列举读目录 inode 的 page cache，内存空闲时冻结（返回旧文件列表），感知车机新写是【概率性】的**（依赖内存压力挤出 page）；单文件路径 open 的 dentry miss 才强制读盘。后台任务（bg_preview scan）发现新事件不能依赖 listdir——需前台 drop_caches 解锁或接受概率。推论：无人访问时「后台自动生成缩略图」与「零 drop（UI_a112 防护）」本质冲突，只能事件驱动前台刷（事件写完 ≥2min 间隙）+ `_coherency_loop` A1 延迟兜底折中 |
