| M90 | **「防抖冷却」用在「无网恢复」路径上会否决唯一可连候选，把「能救」误判成「救不了」（10-03 实证 / v0.3.1.60 修复）**：与 M89 同一事故（R2 放大器）。`full_check` 的「网络连接异常→尝试重连」分支对每个可用网络调 `_switch_to(ssid)`，而 `_switch_to` 首行 `if not self._can_switch(): return False` 会因 **300s 切换冷却**直接否决——日志实证 07:29:09 扫描到 `YL-MIFI-000500`（信号 100%、完全可用），07:29:10 却打印「切换冷却中，跳过切换到 YL-MIFI-000500」（距上次切换 07:25:11 仅 4min）→ `reconnected=False` → 「所有网络均无法连接」→ **凭空多开一次 AP**。冷却本意是防「两个好网络之间来回抖动切换」，却作用在了「我现在没网、请连上任何能连的」恢复路径上。修复：`_switch_to(ssid, force=False)` 增参数——**恢复路径（`full_check` 重连两处）传 `force=True` 绕过冷却**；**前台「切到更优网络」保持 `force=False`**（冷却防抖语义保留）；绕过时打印「恢复路径强制切换（绕过切换冷却）」留证。**通用规则：同一条「冷却」不能同时约束「优化型切换（有网时选更优）」与「恢复型切换（无网时求可用）」——后者必须可绕过，否则冷却会把「唯一候选」也否掉，制造出比它要防的问题更严重的故障。** |
