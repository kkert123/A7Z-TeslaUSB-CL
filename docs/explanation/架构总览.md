## 一句话

一台小单板电脑伪装成 U 盘插在特斯拉上，把车机写进来的视频转手推到微信、NAS 和云端。

## 关键设计决策

### 1. `config.py` 是路径的唯一来源

**决策**：所有模块从 `config.py` 导入路径常量，禁止硬编码。

**理由**：历史上 `sentry_events.json` 在两个模块里写成了不同路径，一个写一个读，数据永远对不上（M19）。这类 bug 排查成本极高且不报错。

**代价**：多一层间接。可接受。

### 2. Present 模式分区只读挂载

**决策**：车机写盘时，本机只读挂载 `/mnt/teslacam`。

**理由**：两边同时写同一个 exFAT 分区必然导致文件系统损坏。exFAT 没有日志，坏了基本修不回来。

**代价**：缓存不会自动失效，读到的可能是旧内容。整个[缓存一致性](缓存一致性.md)机制都是为这个代价买单。

### 3. `utils/` 模块不得依赖 Flask 上下文

**决策**：`utils/` 下所有模块必须能独立运行，不假设 `app` / `session` 存在。

**理由**：这些模块会被 watchdog、systemd timer、CLI 脚本调用，那些场景里没有 Flask app（M31）。

### 4. 子进程调用必须节流

**决策**：任何封装外部命令的调用都要加 TTL 缓存，建议 ≥30 秒。

**理由**：`nvme smart-log` 每 5 秒调一次，10 分钟 197 次，日志刷屏把 Web 拖垮（M34）。959MB 内存扛不住进程风暴。

### 5. systemd timer 必须随包分发 + 幂等自愈

**决策**：timer 加进 `MANAGED_FILES` 白名单，同时常驻服务里加 `ensure_*_timers()` 幂等自愈。

**理由**：timer 是「无主资产」，不随代码更新自动生效。一次清理或换机就永久丢失，而且不报错（M45）。

### 6. 通知的部分成功必须显式处理

**决策**：图文推送必须两部分都成功才算成功；重试时用 `skip_text` 只补缺失的图。

**理由**：只发文字不发图，用户看到的是「通知收到了但没内容」，还不如明确报失败（M47）。

### 7. 升级包带 SHA-256 + Ed25519 验签

**决策**：升级包签名，设备端用内置公钥验签后才执行。

**理由**：设备常年在外网，升级通道必须防篡改。私钥 `upgrade_key` 本地保管，不进仓库。

## 数据流：一次哨兵事件

```
车机写 SentryClips/xxx.mp4
    ↓
sentry_watchdog 检测（listdir 指纹）
    ↓
记录 sentry_events.json
    ↓
bg_preview_generator 生成缩略图（CPU 自适应）
    ↓
weixin_notifier 推送（图文分离，重试补图）
    ↓
push_health.json 记录结果
```

同步与云归档是独立的 timer 驱动链路，不在这条路径上。

## 技术栈

| 层 | 选型 |
|----|------|
| 语言 | Python 3.9（注意：**不支持** `dict \| None` 语法，用 `Optional[dict]`） |
| Web | Flask + Jinja2 |
| 前端 | 原生 JS + CSS，移动优先（mobile-drawer 导航） |
| 进程管理 | systemd（service + timer） |
| 网络 | NetworkManager + hostapd + dnsmasq |
| 云同步 | rclone（14 家服务商） |
| 升级 | tar.gz + SHA-256 + Ed25519 |

## 已知约束

| 约束 | 影响 |
|------|------|
| 959MB 内存 | 并发转码 ≤2 路；所有缓存要设上限 |
| Debian 11 / Python 3.9 | 不能用 3.10+ 语法 |
| exFAT 无日志 | 文件系统损坏基本不可修，fsck 每周必跑 |
| A733 无硬件编解码 | 转码走软编，见 [硬件编解码现状](硬件编解码现状.md) |
| AIC8800 单射频 | station 与 AP 互斥，切换有 10~30s 扫描延迟 |
