# Web 认证方案 B 细化评审 —「密码 + 邮箱动态验证码」

> 状态：**设计评审（不含代码实现）**。日期 2026-11-04。
> 评审对象：用户提出的 B 方案细化设计——密码 + 动态口令；有网络走动态口令、无网络切密码；动态口令经安全邮箱发 6 位数字；设置页增加「安全邮箱 / 发送邮箱」配置。

## 0. 结论摘要

| # | 判断 |
|---|------|
| 1 | 方向可行，但**「无网络 → 只验密码」是一个降级漏洞**：攻击者只要让设备发不出邮件（断网、封 SMTP 端口、把车开到无信号处），就能把双因子压缩成单因子。**这是本方案最需要补的一处**。 |
| 2 | 判定条件不能用「有没有网络」，要用**「发码通道是否可用」**——网络通 ≠ SMTP 可用（运营商封 25 端口、DNS 失败、TLS 过期、服务商限流）。 |
| 3 | **设备时钟实测不可信**：本机 11-04 09:25 开机，直到 **10:53 才完成首次 NTP 同步（87 分钟）**，期间还有一次超时，历史日志出现过 `clock time jumped backwards`。OTP 有效期/锁定窗口全依赖时钟 → 必须有「时钟未同步」分支。 |
| 4 | 邮箱验证码的**第二因子强度 ≈ 邮箱本身的强度**（手机邮件 App 常驻登录时，它基本等于「密码 + 密码」）。要如实认知，别把它当硬件令牌。 |
| 5 | 现成资产可复用：`templates/login.html`（253 行，含用户名/密码表单与 loading 动画）**已在升级包白名单里但没有任何路由渲染**；设置页 `templates/system.html` 已有 9 个 `grp-*` 分组。实施成本比从零做低。 |

## 1. 事实基线（评审依据，均实测）

| 项 | 实测结果 | 对设计的影响 |
|----|---------|-------------|
| 邮件能力 | 全仓库 `grep smtplib/SMTP` **零命中** | 邮件通道是**全新依赖**，需新增发送模块 + 失败重试 + 送达率处理 |

## 2. 补充项

### 2.1 在线/离线判定、认证流程与异常处理

#### 2.1.1 不要用"两态"，用三态

| 状态 | 触发条件 | 认证方式 |
|------|---------|---------|
| `ONLINE` | 发码通道验证通过（见 2.1.2） | **密码 + 邮箱验证码** |
| `DEGRADED` | 通道探测失败，但设备有网 | **密码 + 离线恢复码**（同时提示"可重试发码"） |
| `OFFLINE` | 无默认路由 / 无 DNS | **密码 + 离线恢复码**（或「离线专用密码」，见 2.3.2） |

> 关键：**任何状态都不是"只验密码"**。降级改变的是"第二个因子从哪来"，不是"要不要第二个因子"。

#### 2.1.2 判定条件（分层，禁止用 ICMP ping）

| 层 | 判据 | 超时 | 说明 |
|----|------|------|------|
| L1 链路 | 默认路由存在（`ip route` 有 default） | 即时 | ping 通不代表能发信，很多网络禁 ICMP |
| L2 DNS | 解析 SMTP 域名成功 | 2s | DNS 失败是最常见的"假在线" |
| L3 TCP | 连上 SMTP 端口（优先 587/465，避免 25） | 3s | 运营商/企业网普遍封 25 |
| **L4 应用（强判据）** | **最近一次真实发信成功**（`last_mail_ok_at`） | — | 只有 L4 新鲜（≤10 分钟）才视为通道可用 |

判定顺序：先看 L4 缓存 → 不新鲜再做 L1→L2→L3 探测。**总探测时间上限 5 秒**，不能让登录页卡住。

#### 2.1.3 认证流程（在线）

1. **先验密码，再发码**——否则任何人都能触发发码，把邮箱打出限流（发码轰炸）。
2. 密码通过 → 生成 OTP → **同步发信** → 返回 `sent`（不返回 OTP 本身）。
3. 前端显示 6 位输入框 + 「重发（60s）」+ 「用恢复码登录」两个出口。
4. 验证通过 → **旋转 session id** → 记录审计 → 跳转。

#### 2.1.4 认证流程（DEGRADED / OFFLINE）

- 密码通过 → 提示「当前无法发送验证码」→ 输入**离线恢复码**（一次性）。
- 恢复码使用 → 立即作废 + 强制告警 + 审计标记 `login_method=recovery`。

#### 2.1.5 异常处理矩阵

| 情况 | 处理 |
|------|------|
| 密码错 | **不签发 OTP**，只记失败计数 |
| 密码对但发信失败 | 转 `DEGRADED`；对已通过密码验证者展示摘要（如"SMTP 认证失败"），对未验证者不透露任何细节 |
| 时钟未同步 | **拒绝签发 OTP**（否则有效期判定错乱），提示"设备时间未同步"，放行恢复码 |
| 用户没收到邮件 | 「重发」60s 冷却；同时引导「用恢复码」；连续 2 次重发无果 → 提示检查垃圾箱/转发规则 |
| 并发登录 | 允许多会话（家庭场景），OTP 与发起它的会话绑定，不互相作废 |
| 同一 OTP 二次使用 | 拒绝 + **立即告警**（重放信号） |
| 升级/重启中 | 认证服务不可用返回 503，前端显示"设备正在升级，请稍候"——不要返回 401 让用户以为密码错 |

### 2.2 验证码全生命周期（有效期 / 重试 / 限流 / 防重放 / 锁定 / 审计）

#### 2.2.1 参数建议

| 项 | 建议值 | 理由 |
|----|--------|------|
| 位数 | 6 位数字（`secrets.randbelow(10**6)` 补零） | 体验优先；安全性靠限流兜底，不靠位数 |
| 有效期 | **5 分钟**（可配 3–10） | 兼顾邮件延迟与窗口 |
| 单码可试次数 | **3 次**，超限即作废 | 3/10⁶ = 3e-6 命中率 |
| 重发冷却 | 60 秒 | 防连点 |
| 单次登录最多重发 | 3 次 | 防把邮箱打爆 |
| 单 IP 签发限流 | 10 分钟 ≤5 次 | — |
| 全局签发限流 | 10 分钟 ≤10 次；**每日 ≤20 次** | 服务商（QQ/163 等）日发信量有限 |
| 密码失败锁定 | 连续 5 次 → 锁 15 分钟（按 IP） | — |
| 全局失败锁定 | 10 次 → 锁 30 分钟 | 防换 IP 绕过 |
| OTP 失败锁定 | 累计 10 次 OTP 错 → 锁 30 分钟 | — |

> **安全性来源是"限流 + 一次性 + 短窗口"，不是 6 位数字本身**。文档要把这点写清楚，避免后续有人把限流当"可选优化"删掉。

#### 2.2.2 防重放

- OTP **不存明文**，存 `HMAC-SHA256(otp, 服务器密钥 + 随机盐)`。
- 校验用恒定时间比较（`hmac.compare_digest`）。
- **消费必须原子**：验证通过立即置为 `used`，并发请求只有一个能成功（文件锁 / sqlite 事务；设备是单机，不要用内存标志）。
- 建议附带"绑定上下文"（弱绑定）：记录签此时的 IP/UA，验证时不强制匹配（家庭 NAT 会变），但**不匹配时提升告警级别**。

#### 2.2.3 审计与告警

审计字段（每次登录尝试一行）：`时间(UTC)`、`结果`、`方式(password/otp/recovery)`、`IP`、`UA`、`失败原因码`、`是否命中锁定`、`时钟是否已同步`。

告警（走现有企微通道）：
- 登录成功且 **IP 或 UA 与上次不同** → 推「新设备登录」
- 连续失败 3 次 / 触发锁定 / 使用恢复码 / 修改安全邮箱 → **必推**
- **告警去重**：同 (IP, UA, 事件类型) 30 分钟内只推一次（M114 教训：不该刷屏的地方刷屏，会淹没真告警）
- 断网时告警**入本地队列**，网络恢复后补发（可复用现有 `notify-retry` 机制）

### 2.3 启用 / 降级 / 恢复

#### 2.3.1 首次启用（有前置条件）

1. **只允许在本地网络或本机执行**（`127.0.0.1` / 局域网 / AP 段），禁止从 tailnet 远程首次启用——防"远端抢先配置"。
2. 顺序：设置密码 → 填安全邮箱 + 发送邮箱 → **发测试码 → 回填测试码**（闭环）→ **生成 10 组恢复码并强制展示一次**（要求用户下载/打印）→ 启用。
3. **未完成闭环验证不允许启用**：否则用户以为配好了，实际收不到码 → 自锁。

#### 2.3.2 降级（在线 → 离线）

| 方案 | 说明 | 风险 |
|------|------|------|
| **D1（推荐）：恢复码** | 离线用「密码 + 恢复码」，始终保持双因子 | 恢复码需用户妥善保管 |
| D2：离线专用密码 | 设置一个**与在线密码不同**的密码，仅在本地网络有效 | 单因子，但限制在物理可达范围 |
| D3（不推荐）：直接用登录密码 | 等同把双因子降为单因子，且攻击者可主动制造断网 | **不建议采纳** |

> 若坚持 D3，必须叠加三个约束：① 只在本地网络可用（`127.0.0.1`/局域网/AP 段）② 每次使用都告警 ③ 设置项里明确标注风险并由用户勾选确认。

#### 2.3.3 变更与恢复

| 操作 | 要求 |
|------|------|
| 改密码 | 当前密码 + （OTP 或恢复码） |
| 改安全邮箱 | 当前密码 + **旧邮箱 OTP** → 新邮箱完成测试闭环 → **新旧邮箱都发通知** |
| 改发送邮箱 | 同上 + 测试发信闭环；**禁止把发送邮箱配成与安全邮箱相同**（否则一账号失守即双因子失效） |
| 关闭双因子 | reauth + 二次确认 + 告警；关闭后 24 小时内每次登录都提示「双因子已关闭」 |
| 恢复码用尽 | 设置页显示剩余数量；≤2 组时提醒重新生成（需密码 + OTP） |
| 全部丢失 | **物理恢复**：SSH 登录执行 `reset-auth`（需 sudo），或插入 U 盘放置 `reset_auth.flag`。必须记审计 + 恢复后强制重设 + 网络恢复后补发告警 |

### 2.4 设置页配置项与校验

#### 2.4.1 新增 `grp-security` 分组（放在 `system.html`）

| 字段 | 类型 | 校验规则 | 权限 | 展示 |
|------|------|---------|------|------|
| `security_email` | string | RFC 5322 简化正则；长度 ≤254；**必须已验证**（发过测试码并回填） | 修改需 reauth | 脱敏 `a***@qq.com` |
| `smtp_host` | string | 域名或 IP；≤253 | 修改需 reauth | 明文 |
| `smtp_port` | int | 1–65535，白名单推荐 587/465 | 同上 | 明文 |
| `smtp_tls` | enum | `starttls` / `ssl` / `none`（`none` 需二次确认） | 同上 | 明文 |
| `smtp_user` | string | 非空；≤254 | 同上 | 脱敏 |
| `smtp_password` | string | 非空；≤128；**写入后永不回显** | 同上 | 仅显示 `已配置` |
| `otp_ttl` | int | 180–600 秒，默认 300 | 同上 | 明文 |
| `dual_factor_enabled` | bool | 关闭需 reauth + 确认 | 同上 | 明文 |
| `recovery_codes_remaining` | int（只读） | — | 只读 | 明文 |

#### 2.4.2 校验与权限规则（补充）

1. **保存前必须能"验证"**：SMTP 配置提供「发送测试邮件」按钮，只有收到测试码并回填通过才允许保存——**不允许"保存了但不可用"的中间态**。
2. **SMTP 密码只写不读**：`GET` 接口返回 `has_password: true/false`，永不返回明文；前端不缓存。
3. **首次配置仅本地网络**（同 2.3.1）。
4. **敏感变更需 reauth**：5 分钟内刚通过二次认证才允许改邮箱/密码/开关。
5. **所有设置写操作要 CSRF token**，`Content-Type: application/json` 才接受（挡表单跨站）。
6. **未认证状态不泄露配置细节**：登录页最多提示"验证码通道未配置，请联系管理员"，不显示邮箱、不显示 SMTP 状态。
7. **不允许从"未验证的邮箱"发码**：安全邮箱处于 `pending` 时，验证码只能发到旧邮箱/走恢复码。

### 2.5 边界情况（补充清单）

| # | 情况 | 处理 |
|---|------|------|
| 1 | 设备在 AP 模式下（无外网） | 强制 `DEGRADED/OFFLINE`，必须能密码 + 恢复码登录（这是最需要访问设备的时刻，不能把用户锁在门外） |
| 2 | 车在移动、WiFi 在热点/家宽间切换 | 会话不因网络切换失效；发码前重新探测，失败快速转 DEGRADED |
| 3 | 邮件延迟 10 分钟才到 | 提示"验证码可能延迟，过期请重发"；不要因延迟自动作废会话 |
| 4 | 用户同一时间开两个标签页登录 | 各自独立 OTP，互不作废；但共享失败计数 |
| 5 | 设备时钟回跳（历史出现过） | 已签发 OTP 的 `expire_at` 用**签发时的时间戳 + TTL**，不用"当前时间 - created"重新算；时钟回跳时拒绝签发新码 |
| 6 | 时区 | 审计与过期判断一律 UTC 时间戳，展示时才转本地 |
| 7 | 邮件被自动转发 | 提示用户检查邮箱转发规则（验证码外泄途径） |
| 8 | 邮箱服务商限流/拒信 | 记录 SMTP 响应码；每日签发上限 20；超限时明确提示"今日发码次数已用尽，请用恢复码" |
| 9 | 恢复码被拍照存相册 | 文档明确建议打印或存密码管理器，不存相册/聊天记录 |
| 10 | 升级后会话失效 | `secret_key` 必须落盘（`/data/.secret_key`），否则每次升级所有人被登出（用户会以为"又坏了"） |
| 11 | 多人共用一个口令 | 审计无法区分"谁"，只能记 IP/UA；需要区分则要二期做多账号 |
| 12 | 浏览器自动填充把 OTP 当密码存 | 登录页 OTP 字段加 `autocomplete="one-time-code"`，密码字段 `autocomplete="current-password"` |

## 3. 风险

| ID | 风险 | 概率 | 影响 | 缓解 |
|----|------|------|------|------|
| R1 | **降级攻击**：攻击者制造断网/封锁 SMTP → 单因子 | 高 | **高** | 采纳 D1（恢复码）保持双因子；禁用 D3 |
| R2 | **邮箱被控 = 双因子失效** | 中 | 高 | 安全邮箱开强密码 + 二次验证；与发送邮箱**不同账号**；变更双通道通知 |
| R3 | **SMTP 凭据可被读取**（设备 root 可解密） | 中 | 高 | 用「应用专用密码/仅发信」账号；AES-GCM 加密 + 文件 0600；明确"防不了物理接触"的边界 |
| R4 | **邮件不达 / 进垃圾箱 / 服务商限流** | 高 | 中 | 闭环验证（测试码回填）；重发冷却 + 恢复码出口；每日发码上限 |
| R5 | **时钟不可信**（实测开机 87 分钟才同步） | **高** | **高** | 时钟未同步拒签 OTP；`expire_at` 用签发时戳；优先用单调时钟做窗口 |
| R6 | **DoS 自锁**：攻击者刷发码耗尽配额，主人进不去 | 中 | 高 | 全局配额 + **本地网络优先通道**（配额耗尽时 127/局域网仍可登录） |
| R7 | 家庭 NAT 共用出口 IP，限流互相误伤 | 中 | 低 | 限流按 IP+UA 组合；本地区域用更宽阈值 |
| R8 | **告警风暴**（M114 翻版） | 中 | 中 | 同 (IP,UA,事件) 30 分钟冷却；断网入队补发 |
| R9 | **配置写入非原子**（`config_manager` 现用 `json.dump` 直写） | 中 | 中 | 存凭据前先把 `save_config` 改成 `mkstemp + os.replace`（复用 M114 修法） |
| R10 | 恢复码保管不当（截图/聊天记录） | 中 | 高 | 只显示一次；建议打印/密码管理器；使用即告警 |
| R11 | 会话固定 / 升级丢会话 | 中 | 中 | 登录成功 rotate session；`secret_key` 落盘 |
| R12 | 日志泄露敏感信息 | 低 | 高 | 审计日志禁止记录 OTP/密码/SMTP 密码；日志文件 0600 |
| R13 | 单账号无法追责 | 高 | 低 | 二期多账号；当前靠 IP/UA 归因 |

## 4. 建议（按优先级）

### P0 — 必须做，否则方案不安全

1. **消除「离线 = 单因子」**：改为「密码 + 恢复码」；如需单密码，只允许本地网络 + 显式开关 + 每次告警。
2. **判定用"发码通道可用性"**（L4 应用层判据），不要用 `ping` / "有 WiFi"。
3. **时钟未同步时拒绝签发 OTP**，并把"时钟已同步"写进审计。（实测依据：本机开机后 87 分钟才同步）
4. **配置闭环验证**：SMTP/安全邮箱保存前必须"发测试码 → 回填成功"。
5. **限流 + 锁定 + 本地网络优先通道**三件套，缺一不可（限流防爆破、锁定防慢速爆破、本地通道防自锁）。
6. **凭据加密存储 + 配置文件原子写**（先把 `save_config` 改成原子写，再存密码/邮箱凭据）。

### P1 — 应该做

7. 登录成功 rotate session；`secret_key` 落盘；Cookie `HttpOnly + SameSite=Lax`，OTP 字段 `autocomplete="one-time-code"`。
8. 审计（含"方式/IP/UA/时钟状态"）+ 告警去重 + 断网队列补发。
9. 变更邮箱/密码/开关一律 **reauth + 双通道通知 + 强制注销其它会话**。
10. **物理恢复通道**（SSH `reset-auth` / U 盘 `reset_auth.flag`）写进文档，且恢复后强制重设。
11. 恢复码：10 组 × 10 位 base32（去 0/O/1/l），只显示一次，设置页显示剩余数量。

### P2 — 可以后做

12. **用 TOTP 替代邮箱验证码作为主第二因子**：无网络也能用、不依赖邮件送达率，能一举消灭 R1/R4/R5 三个风险。代价：需要验证器 App + 设备时钟准确（可要求"时钟已同步"才允许启用 TOTP）。邮箱验证码降级为"TOTP 设备丢失时"的备用通道。
13. 多账号 / 角色（家人只看视频）。
14. WebAuthn / passkey（若常用浏览器支持，可彻底免 OTP）。

### 术语建议

- 「**动态口令**」建议专指 TOTP（时间同步一次性口令）；
- 本方案的 6 位邮件码建议叫「**邮箱验证码**」。
- 两者混称会在实现和文档里造成歧义（例如"离线时动态口令不可用"——TOTP 恰恰离线可用）。
