## 0. 决策基线（逐条标注边界与后果）

| # | 决策 | 实现边界（不可越线） | 已知后果 |
|---|------|---------------------|---------|
| D1 | 在线判定以「最近一次真实发信成功」为强判据，10 分钟内视为新鲜 | 不用 `ping`/不用"有 WiFi"判定；`last_mail_ok_at` 必须在**发信返回 SMTP 250 后**才更新 | 邮件成功但对方退信时仍判为 ONLINE（下一次真实登录会暴露） |
| D2 | 靠发信频率限制防"点登录就轰炸" | **密码通过后才发码**（未通过密码不触发任何邮件）；限流作为第二道闸 | 攻击者无法用匿名请求触发发信；代价是必须先知道密码才能收码 |
| D3 | 6 位码统一叫「邮箱验证码」；「动态口令」仅指 TOTP | 代码命名 `email_code`；`totp_*` 本期**不实现**，仅预留命名空间 | 文档/日志/UI 文案必须一致，禁止出现"动态密码/动态码"混称 |
| D4 | 离线兜底用「直接密码」，不采用恢复码，暂不引入 TOTP | **离线直连登录只在本地网络可用**（`127.0.0.1` / 局域网 / AP 段），tailnet 远程**不允许** | 等价于接受"降级为单因子"的风险；缓解见 §9-R1。用户不在本地网络且无外网时**无法登录** |
| D5 | 单账号 | 用户名固定 `admin`，无注册、无多用户、无角色；审计里账号恒为 `admin` | 审计无法区分"谁"，只能靠 IP/UA 归因 |
| D6 | 首次启用仅本地网络，且必须完成「发测试码→回填」闭环后才允许保存 | 未完成闭环时配置处于 `unverified`，**不生效**（不影响登录，但也不算已启用） | 远程（tailnet）无法完成首次配置，必须回家或在设备旁操作 |
| D7 | 安全邮箱禁止从 tailnet 远程修改，只能通过正常 Web 页面 | 判据三重叠加：来源属本地网络 + 已登录会话 + 表单页面（CSRF + 同源 Referer）；**API 直调一律 403** | 人在外地且邮箱失效时无法自助修改，只能走 §6.5 应急通道 |

> **决策冲突已消解**：D6/D7 都要求"本地网络"，因此系统需要一个明确的**本地网络判定**（§4.2）。除这两处外，其余接口允许 tailnet 访问。

## 1. 与参考页 `ups_stats.php` 的对照

参考页（http://12.127.12.228/ups_stats.php）实测结构：Bootstrap 5 白卡片 + 两个 tab（密码登录 / 邮箱验证）+ 60 秒倒计时 + 脱敏邮箱提示 + `fetch` 返回 `{status, msg}`。

### 借鉴（视觉与交互）

| 借鉴点 | 说明 |
|--------|------|
| 单卡片居中布局 | 400px 宽、12px 圆角、浅灰底、轻阴影 |
| 验证码按钮 60 秒倒计时 | 按钮文案 `发送中...` → `60s` → 恢复；成功后置灰 |
| 脱敏邮箱提示 | `cnl***@cnlvan.cn`，让用户知道码发到哪 |
| `form-text` 辅助说明 | 按钮下方一行小字 |
| 返回 `{status, msg}` 并 `alert` | 简单直接，不引入 toast 体系 |

### **不借鉴**（逻辑差异，必须点明）

| 差异 | 参考页 | 本方案 | 原因 |
|------|--------|--------|------|
| **认证关系** | 两个 tab，**二选一**（密码 OR 验证码） | **先后两步，两个都要**（密码 AND 验证码） | 用户要的是双因子；tab 结构会让人误以为可以只填验证码 |
| **验证码前置条件** | 未认证即可点「获取验证码」 | **密码通过后才发码**（D2） | 防止匿名轰炸邮箱 |
| **前端依赖** | Bootstrap 5 走 jsDelivr CDN | **不引任何 CDN**，沿用 A7Z 自有 `static/style.css` | **A7Z 常在无外网环境运行**（AP 模式/车内），CDN 拉不到会导致登录页样式崩坏、按钮错位。这是设备与服务器的本质差异 |
| **CSS 变量/主题** | 固定浅色 | 跟随 A7Z 现有 `data-theme`（深/浅色） | 与全站一致 |
| **CSRF** | 无 | 所有 POST 必须带 CSRF token | 参考页是公网独立页面，A7Z 需与全站一致 |

> 结论：**照抄视觉，不照抄结构**。登录页改造是在现有 `templates/login.html`（253 行，已有表单与 loading 动画）上做，只新增"第二步验证码"，不重写。

## 4. 在线/离线判定

### 4.1 判据（D1）

```
ONLINE  := (now - last_mail_ok_at) <= 600s
```

- `last_mail_ok_at` 只在 **SMTP 服务器返回 250（已接收）** 后更新；DNS 失败、认证失败、超时、限流拒信都不更新。
- 超过 600 秒 → 进入 `UNKNOWN`，此时**不阻塞用户**：仍显示验证码输入框，但提供"发送验证码"按钮；点击时实时探测一次（L1 默认路由 → L2 DNS 2s → L3 TCP 587/465 3s，总超时 5s）。
  - 探测成功 → 发码，成功则回到 ONLINE。
  - 探测失败 → 提示"当前无法发送验证码"，并展示离线直连入口（仅本地网络可用）。
- **不缓存"离线"结论超过 60 秒**（网络恢复要能快速回来）；缓存"在线"结论 10 分钟。

### 4.2 本地网络判定（D4/D6/D7 共用）

```
is_local_network := remote_addr ∈ {127.0.0.1/8, <LAN_CIDR 配置项>, 192.168.42.0/24}
tailnet 段 100.64.0.0/10 → 明确判定为 非本地
```

- `<LAN_CIDR>` 从配置读取，默认包含设备当前网卡所在网段（启动时采集一次 + 设置页可配）。
- **不信任 `X-Forwarded-For`**（当前无反代；信任 header 等于自废）。
- 判定结果写入审计，便于事后核对。

## 5. 认证流程

### 5.1 首次启用（D6）

```
[本地网络校验] → 设置密码 → 填安全邮箱 + SMTP 配置
  → [测试发信] → 回填测试码 → 校验通过 → 保存为 verified → enabled=true
```

- 非本地网络访问设置页时：`grp-security` 整块**只读**，并显示"安全配置仅限本地网络修改"。
- 未完成闭环：`enabled=false`，登录走"仅密码 + 醒目提示'双因子未启用'"。
- **不生成恢复码**（D4）。

### 5.2 在线登录（主路径）

```
① POST 密码  ──失败──> 失败计数+1（锁定判定）→ 401 4001
        └──成功──> ② 生成邮箱验证码 → SMTP 发信
                       ├─ 发信成功 → 更新 last_mail_ok_at → 200 {need_email_code:true, sent_to:"a***@x.cn", cooldown:60}
                       └─ 发信失败 → 500/401 4006 + {fallback_available: is_local_network}
③ POST 验证码 ──失败──> 该码尝试次数+1（≥3 作废）→ 401 4003
        └──成功──> 建立会话（rotate session id）→ 审计 → 200
```

- 密码校验与发码在**同一次请求**内完成，避免两步之间被插队。
- 前端：密码框 `autocomplete="current-password"`；验证码框 `autocomplete="one-time-code"`；验证码输入框仅"密码通过"后才渲染（或渲染但禁用）。

### 5.3 离线直连登录（D4）

```
[本地网络校验] ──非本地──> 403 4007（明确告知"离线登录仅限本地网络"）
        └──本地──> POST 密码 → 成功即建立会话
                     → 审计 login_method=local_password
                     → 强制企微告警（每次，含 IP/UA）
```

- UI 上必须是**用户显式选择**的入口（"无法接收验证码？使用本地密码登录"），**不自动降级**。
- tailnet 远程即使设备离线，也只能看到 403 + 提示"请到设备所在局域网登录"。

### 5.4 修改安全邮箱（D7）

```
[本地网络] + [已登录] + [5 分钟内 reauth] + [页面表单(CSRF+同源 Referer)]
  → 输入新邮箱 → 发测试码到新邮箱 → 回填 → 保存
  → 旧邮箱 + 企微 双通道通知
  → 强制注销其它会话
```

- 任一条件不满足：403 4007 / 4008 / 403。
- **API 直调拒绝**：即使带合法 session + token，只要不满足"同源 Referer + CSRF"，一律拒绝。

### 5.5 忘记密码（本期边界）

- 本期**不做**自助重置（D4 不采用恢复码，也没有第二个可信通道）。
- 应急通道（写进文档，运维用）：SSH 登设备执行 `reset-auth`（需 sudo）→ 清空 `web_auth` → 下次访问重新走首次启用（仅本地网络）。操作记审计 + 告警。

## 6. 邮箱验证码生命周期

| 项 | 值 | 说明 |
|----|-----|------|
| 生成 | `secrets.randbelow(10**6)` 补零 6 位 | **禁止 `random`** |
| 存储 | `HMAC-SHA256(code, server_secret + salt)` | 不存明文 |
| 有效期 | **300 秒**（可配 180–600） | 见 §6.2 时钟处理 |
| 单码可试 | **3 次**，超限作废 | 3/10⁶ 命中率 |
| 重发冷却 | 60 秒 | 前端倒计时 + 后端硬校验 |
| 单会话最多重发 | 3 次 | 防打爆邮箱 |
| 单 IP 签发 | 10 分钟 ≤5 次 | — |
| 全局签发 | 10 分钟 ≤10 次；**每日 ≤20 封** | 对齐 QQ/163 等服务商日限 |
| 一次性 | 验证成功立即作废（**原子消费**） | 并发只有一个成功 |
| 比较 | `hmac.compare_digest` | 恒定时间 |

### 6.1 防重放

- 消费采用"读-改-写"加**文件锁**（`fcntl.flock` 或 sqlite 事务）；禁止仅用内存标志。
- 同一码二次提交 → 401 4003 + **告警**（重放信号）。
- 记录签此时的 IP/UA，验证时不强制匹配（家庭 NAT 会变），但不匹配时**提升告警等级**。

### 6.2 时钟处理（实测：本机开机 87 分钟才 NTP 同步）

- 有效期判断用**单调时钟差值**：签发时同时记 `issued_wall`（展示/审计）与 `issued_mono`（`time.monotonic()`），TTL 判定用 `monotonic() - issued_mono`。
- 好处：NTP 校时/回跳不会让验证码"提前过期"或"永不过期"，**无需因时钟未同步而拒绝发码**。
- 进程重启后 `monotonic` 归零 → 运行态文件里同时存 `issued_wall`，重启后回退到用 wall 时间判断（并在审计里标记 `clock_fallback=wall`）。

### 6.3 审计字段

每次尝试一行（JSONL，`/data/auth_audit.log`，0600，1MB 轮转）：

`ts_utc, result, method(password/email_code/local_password), ip, ua, fail_reason, locked, clock_synced, is_local_network`

> **新增日志文件必须登记到 `utils/log_rotator.LOG_FILES`**，否则无界增长（项目铁律）。
> 审计日志**禁止**记录密码、验证码、SMTP 密码。

## 7. 密码策略与锁定

| 项 | 值 |
|----|-----|
| 强度 | ≥10 位，含字母 + 数字（弱口令黑名单校验） |
| 存储 | `pbkdf2_hmac('sha256', pwd, salt, 200_000)`（标准库，无新依赖） |
| 失败锁定 | 单 IP 连续 5 次 → 锁 15 分钟；全局 10 次 → 锁 30 分钟 |
| 锁定粒度 | 仅锁"密码校验"，不锁"已登录会话" |
| 解锁 | 到期自动解除；设置页可手动清除（需已登录 + reauth） |
| 密码变更 | 需当前密码 + 邮箱验证码（或本地网络下当前密码）→ 变更后**注销其它会话** |

> **离线场景例外**：本地网络 + 全局锁定中时，**密码校验仍放行一次/5 分钟**（防"攻击者刷锁定把主人锁在门外"，R6）。该放行必记审计。

## 10. 审计与告警

| 事件 | 是否推送 | 冷却 |
|------|---------|------|
| 登录成功（IP 或 UA 变化） | ✅ | 同 (IP,UA) 30 分钟 |
| **离线直连登录** | ✅ **必推** | 30 分钟 |
| 连续失败 3 次 / 触发锁定 | ✅ | 30 分钟 |
| 安全邮箱变更 | ✅ 新旧邮箱 + 企微 | 无（一次性事件） |
| 双因子被关闭 | ✅ | 无 |
| 应急重置（`reset-auth`） | ✅ | 无 |

- 断网时告警入本地队列，恢复后补发（复用 `notify-retry`）。
- **告警去重是硬要求**（M114 教训：刷屏会淹没真告警）。

## 11. 安全边界与残余风险

| ID | 风险 | 状态 | 缓解 |
|----|------|------|------|
| **R1** | **离线降级为单因子**（D4 明确接受） | ⚠️ 已知并接受 | 仅本地网络可用 + 每次必告警 + 强密码（≥10 位）+ 审计可查 + UI 明示"当前离线，仅密码可用" |
| R2 | 邮箱被控 = 双因子失效 | 部分缓解 | 安全邮箱与发送邮箱**必须不同账号**；发送邮箱用「应用专用密码/仅发信」权限；变更双通道通知 |
| R3 | SMTP 凭据可被 root 解密 | 接受 | 文件 0600 + AES-GCM；明确边界：**防不了物理接触** |
| R4 | 邮件不达/进垃圾箱/服务商日限 | 缓解 | 闭环验证 + 每日 20 封上限 + 离线入口兜底 |
| R5 | 时钟不可信 | **已解决** | 用单调时钟做 TTL（§6.2），重启后回退 wall 时间并标记 |
| R6 | 限流/锁定被刷导致自锁 | 缓解 | 本地网络 + 全局锁定中仍放行密码（1 次/5 分钟） |
| R7 | 家庭 NAT 共用 IP 限流误伤 | 缓解 | IP+UA 组合计数；本地网段阈值放宽 |
| R8 | 告警风暴 | 缓解 | 统一 30 分钟冷却 + 队列补发 |
| R9 | 配置/运行态非原子写 | **前置必修** | `save_config` 先改 `mkstemp + os.replace`（M114 修法） |
| R10 | 单账号无法追责（D5） | 接受 | 靠 IP/UA 归因；二期再评估多账号 |
| R11 | D7 导致"人在外地改不了邮箱" | 已知 | 应急通道：SSH `reset-auth`（需 sudo，记审计 + 告警） |

## 12. 实施顺序与验收

### 阶段（每阶段独立可验证，互不阻塞）

| 阶段 | 内容 | 验收判据 |
|------|------|---------|
| P0 | `save_config` 原子写 + 运行态文件 | 并发写 100 次后文件始终合法 JSON（复用 M114 测法） |
| P1 | 认证骨架：`before_request`、会话、CSRF、登录页（密码） | 未登录访问任意页 → 跳 `/login`；API 401；静态资源放行 |
| P2 | 邮箱通道：SMTP 模块 + 验证码 + 限流 + 单调时钟 TTL | 发码→收码→登录成功；3 次错码作废；60s 冷却生效；重启后 TTL 判断不崩 |
| P3 | 设置页 `grp-security` + 闭环验证 + reauth | 非本地网络整块只读；未闭环不能保存；改邮箱需旧邮箱确认 |
| P4 | 离线直连 + 审计 + 告警 + 文档 | 断网时本地可登录、tailnet 403；告警不刷屏 |
